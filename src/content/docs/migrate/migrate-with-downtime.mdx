You use downtime migration to move less than 100GB of data from a {C.SELF_SHORT} database to a {C.SERVICE_LONG}.

Downtime migration uses the native {C.PG} [`pg_dump`](https://www.postgresql.org/docs/current/app-pgdump.html) and [`pg_restore`](https://www.postgresql.org/docs/current/app-pgrestore.html) commands.
If you are migrating from {C.SELF_LONG}, this method works for {C.HYPERTABLE}s compressed into the {C.COLUMNSTORE} without having
to convert the data back to the {C.ROWSTORE} before you begin.

<DoNotRecommendForLargeMigration />

However, downtime migration for large amounts of data takes a large amount of time. For more than 100GB of data, best
practice is to follow [live migration](/migrate/live-migration).

This page shows you how to move your data from a {C.SELF_SHORT} database to a {C.SERVICE_LONG} using
shell commands.

## Prerequisites

<MigrationPrerequisites />

- Install the {C.PG} client tools on your migration machine.

  This includes `psql`, `pg_dump`, and `pg_dumpall`.

- Install the GNU implementation of `sed`.

  Run `sed --version` on your migration machine. GNU sed identifies itself
  as GNU software, BSD sed returns `sed: illegal option -- -`.

<TabItem label="From AWS RDS/Aurora">

To migrate your data from an Amazon RDS/Aurora {C.PG} instance to a {C.SERVICE_LONG}, you extract the data to an intermediary
EC2 Ubuntu instance in the same AWS region as your RDS/Aurora {C.PG} instance. You then upload your data to a {C.SERVICE_LONG}.
To make this process as painless as possible, ensure that the intermediary machine has enough CPU and disk space to
rapidly extract and store your data before uploading to {C.CLOUD_LONG}.

Migration from RDS/Aurora {C.PG} moves the data only. You must manually enable {C.CLOUD_LONG} features like
[{C.HYPERTABLE}s](/learn/hypertables/understand-hypertables), [data compression](/learn/columnar-storage/understand-hypercore) or [data retention](/learn/data-lifecycle/data-retention/about-data-retention) after the migration is complete. You enable {C.CLOUD_LONG}
features while your database is offline.
