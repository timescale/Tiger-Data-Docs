# How to upload a file using the terminal

This guide shows you how to upload **CSV**, **MySQL**, and **Parquet** files from a source machine into your {C.SERVICE_LONG} using the terminal. Use the tab below that matches your file type. Terminal-based imports are ideal for large files, scripting, and automation—and they avoid the size limits of the [Console upload](/migrate/import-console).

## Before you start

### Prerequisites

- A [Tiger Cloud service](/deploy/tiger-cloud/get-started/create-services) with [connection details](/integrate/find-connection-details) (host, port, database, user, password).
- Data files on a machine that can reach your service (your laptop, a jump host, or a server).
- **For CSV:** `psql` (or another {C.PG} client) installed.
- **For MySQL:** Access to the MySQL source (e.g. `mysqldump`, MySQL client) and `psql` for the target.
- **For Parquet:** A way to convert Parquet to CSV if you use `COPY` (e.g. Python, `parquet-tools`), or a loader that supports Parquet; plus `psql` or [timescaledb-parallel-copy](https://github.com/timescale/timescaledb-parallel-copy) for bulk load.

### Supported formats and limits

- **CSV:** Use {C.PG} `COPY` or `\copy` for high-throughput bulk load. UTF-8 recommended; set delimiter and header as needed.
- **MySQL:** Export from MySQL (e.g. `mysqldump` or CSV export), then import into your service with `psql` or `pg_restore` (for dumps). For ongoing sync, see [Sync from Postgres](/migrate/livesync-for-postgresql) or migration guides.
- **Parquet:** Convert to CSV then use `COPY` or timescaledb-parallel-copy, or use a Parquet-capable ETL tool that can write to {C.PG}.

<Callout variant="tip">
Use the same {C.PG} major version as your target when running `pg_dump`/`pg_restore` for dumps. For large CSV or Parquet loads, [timescaledb-parallel-copy](https://github.com/timescale/timescaledb-parallel-copy) can speed up imports.
</Callout>

## How to upload a file

Choose the tab that matches your source file type and follow the steps.

<Tabs>

<TabItem label="From CSV">

To load a CSV file into your service from the terminal:

<NumberedList>

<NumberedItem title="Get your connection string">
Use your [Tiger Cloud connection details](/integrate/find-connection-details) and set a connection string, for example:
`postgres://USER:PASSWORD@HOST:PORT/DATABASE?sslmode=require`
</NumberedItem>

<NumberedItem title="Create the target table (if needed)">
Define a table that matches your CSV columns and types. Example:

```sql
CREATE TABLE my_data (
  time  TIMESTAMPTZ,
  symbol TEXT,
  price  DOUBLE PRECISION,
  volume BIGINT
);
```

</NumberedItem>

<NumberedItem title="Load the CSV with COPY or \copy">
- **From your local machine:** Use `\copy` in `psql` (client-side; file must be on your machine):

```bash
psql "postgres://USER:PASSWORD@HOST:PORT/DATABASE?sslmode=require" -c "\copy my_data FROM 'path/to/file.csv' WITH (FORMAT csv, HEADER true, DELIMITER ',');"
```

- **From a server that can reach the DB:** Use `COPY` in SQL (server-side; file path is on the server) or run `\copy` from a client that has the file. For very large files, consider [timescaledb-parallel-copy](https://github.com/timescale/timescaledb-parallel-copy) for parallel loading.
</NumberedItem>

<NumberedItem title="Verify the import">
Query the table in `psql` or the [SQL editor](https://console.cloud.timescale.com) to confirm row counts and sample data.
</NumberedItem>

</NumberedList>

</TabItem>

<TabItem label="From MySQL">

To get data from MySQL into your Tiger Cloud service using the terminal:

<NumberedList>

<NumberedItem title="Export data from MySQL">
- **Option A — CSV:** Export tables to CSV (e.g. `SELECT ... INTO OUTFILE` or a script that writes CSV), then load with `\copy` or `COPY` as in the **From CSV** tab.
- **Option B — SQL dump:** Use `mysqldump` to create a SQL dump. Note: MySQL dump syntax differs from {C.PG}; you may need to convert or load schema and data in steps (e.g. schema first, then data via CSV).
</NumberedItem>

<NumberedItem title="Get your Tiger Cloud connection string">
Use your [Tiger Cloud connection details](/integrate/find-connection-details):  
`postgres://USER:PASSWORD@HOST:PORT/DATABASE?sslmode=require`
</NumberedItem>

<NumberedItem title="Create the target schema and tables">
Create tables in your Tiger Cloud service that match the data you exported (same column names and compatible types). Adjust types as needed (e.g. MySQL `DATETIME` → `TIMESTAMPTZ`).
</NumberedItem>

<NumberedItem title="Import the data">
- If you exported to **CSV**, use `psql` with `\copy` or `COPY` as in the **From CSV** tab.
- If you have a **MySQL dump**, you can use a conversion step or tool (e.g. [pgloader](https://pgloader.io/) for MySQL → {C.PG}) to load into your service. For schema-only or custom dumps, restore schema first, then load data (e.g. via CSV) to avoid syntax differences.
</NumberedItem>

<NumberedItem title="Verify the import">
Query the tables in `psql` or the [SQL editor](https://console.cloud.timescale.com) to confirm data.
</NumberedItem>

</NumberedList>

<Callout variant="note">
For a full MySQL → Tiger Cloud migration with schema and data, see [Migrate from a specific database](/migrate/migrate-from) and migration guides that cover schema mapping and tools like pgloader.
</Callout>

</TabItem>

<TabItem label="From Parquet">

To load a Parquet file into your service from the terminal:

<NumberedList>

<NumberedItem title="Convert Parquet to CSV (if using COPY)">
{C.PG} `COPY` does not read Parquet directly. Convert the Parquet file to CSV (e.g. with Python/pandas, `parquet-tools`, or another tool), then follow the **From CSV** steps. Example with Python:

```bash
python -c "
import pandas as pd
df = pd.read_parquet('data.parquet')
df.to_csv('data.csv', index=False)
"
```

</NumberedItem>

<NumberedItem title="Get your connection string">
Use your [Tiger Cloud connection details](/integrate/find-connection-details):  
`postgres://USER:PASSWORD@HOST:PORT/DATABASE?sslmode=require`
</NumberedItem>

<NumberedItem title="Create the target table">
Define a table that matches the Parquet/CSV columns and types (infer from the Parquet schema or the CSV header).
</NumberedItem>

<NumberedItem title="Load the data">
Use `\copy` or `COPY` as in the **From CSV** tab, or use [timescaledb-parallel-copy](https://github.com/timescale/timescaledb-parallel-copy) for large files. Point the command at the converted CSV.
</NumberedItem>

<NumberedItem title="Verify the import">
Query the table in `psql` or the [SQL editor](https://console.cloud.timescale.com) to confirm row counts and sample data.
</NumberedItem>

</NumberedList>

</TabItem>

</Tabs>

Your data is now in your Tiger Cloud service. For time-series tables, consider converting them to [hypertables](/build/data-management/understand-hypertables) for better performance.

## Troubleshooting

- **Permission denied:** Ensure your database user has `CREATE` and `INSERT` (and `USAGE` on the schema) on the target tables.
- **Encoding errors:** Use UTF-8 for CSV files and connection encoding to avoid corruption.
- **Connection timeouts:** For large imports, use a stable network; increase timeouts if your client supports it.
- **Foreign key errors:** Create and load tables in dependency order, or temporarily defer constraint checks during import.

## Summary

You can upload CSV, MySQL, and Parquet data into your Tiger Cloud service from the terminal: use **From CSV** with `COPY`/`\copy`, **From MySQL** by exporting to CSV or using a migration tool, and **From Parquet** by converting to CSV then loading. For a UI-based upload, use [Upload a file using the Console](/migrate/import-console); for continuous sync from S3, use [Sync from S3](/migrate/livesync-for-s3).
