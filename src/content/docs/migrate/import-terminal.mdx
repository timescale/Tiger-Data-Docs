## Overview

Learn how to import data into your Tiger Cloud database using terminal-based tools including `psql`, the `COPY` command, and `pg_restore`. Command-line imports are ideal for scripting, automation, and handling large datasets efficiently.

## Prerequisites

- A running Tiger Cloud service with connection details
- `psql` client installed on your local machine
- Connection string or individual credentials (host, port, database, username, password)
- Data files accessible from your local machine (CSV, SQL dump, or custom format)
- Appropriate permissions on the target database

## Import methods

This section covers the primary methods for importing data via the terminal, including when to use each approach.

### Import CSV files with COPY

Use the `COPY` command for high-performance bulk data imports from CSV files. This method minimizes transactional overhead and processes data directly.

#### Using \copy (client-side)

The `\copy` meta-command runs on your local machine and is ideal when your data files are stored locally.

#### Using COPY (server-side)

The `COPY` command runs on the server and requires the file to be accessible from the database server.

### Import SQL dump files

Use `psql` to import SQL dump files generated by `pg_dump` or `pg_dumpall`. This method is useful for restoring backups or migrating data between {C.PG} databases.

#### Basic import command

Import a SQL dump file using the `-f` flag for better error handling and line number reporting.

#### Handling errors during import

Configure error handling behavior using the `--set ON_ERROR_STOP=on` option to stop on first error.

### Import using pg_restore

Use `pg_restore` for importing custom-format or directory-format dumps created by `pg_dump`. This method supports parallel restoration for faster imports.

#### Parallel restore for large databases

Speed up restoration by using multiple concurrent jobs with the `-j` flag.

## Best practices

- Import roles and users before importing database objects to preserve permissions
- Use the `-f` option with `psql` to get error messages with line numbers
- For large databases, use compressed dumps with gzip to reduce file size and transfer time
- Place your client machine close to the database server to minimize network latency
- Vacuum tables before running `pg_dump` to reduce bloat and improve dump times
- Use the {C.PG} binaries from your target version when migrating between versions

## Troubleshooting

### Permission denied errors

Verify that your database user has the necessary privileges to create objects and insert data.

### Encoding issues

Ensure your data files are encoded in UTF-8 to prevent import failures or data corruption.

### Connection timeouts

For large imports, adjust timeout settings or use a more stable network connection.

### Foreign key constraint violations

Import tables in the correct order or temporarily disable foreign key constraints during import.
