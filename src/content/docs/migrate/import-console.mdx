## Overview

Learn how to import data into your Tiger Cloud database using the web console. The console provides a visual interface for uploading CSV files, mapping columns to table schemas, and monitoring import progress without using command-line tools.

## Prerequisites

- An active Tiger Cloud account with console access
- A Tiger Cloud service with a database created
- Data files prepared in a supported format (CSV, TSV)
- Target table created with appropriate schema (or create during import)
- Files sized within console upload limits

## Supported file formats

This section describes the file formats and configurations supported by the console import feature.

### CSV requirements

- UTF-8 encoding recommended
- First row should contain column headers matching target table columns
- Fields containing commas or special characters must be enclosed in double quotes
- Consistent delimiter usage throughout the file

### File size limits

Information about maximum file sizes for console uploads and alternatives for larger files.

## Import workflow

### Step 1: prepare your data

Ensure your CSV file is properly formatted with headers, consistent data types, and no encoding issues.

### Step 2: navigate to import

Access the import feature from your Tiger Cloud console dashboard.

### Step 3: select target table

Choose an existing table or create a new table to receive the imported data.

### Step 4: upload and configure

Upload your file and configure import settings including delimiter, header row, and null value handling.

### Step 5: map columns

Review and adjust the mapping between CSV columns and database table columns. Verify data type compatibility.

### Step 6: preview and validate

Preview the data before import to catch formatting issues or mapping errors.

### Step 7: execute import

Start the import and monitor progress through the console interface.

## Column mapping

### Automatic mapping

The console attempts to match CSV headers to table columns by name. Review these mappings before proceeding.

### Manual mapping adjustments

Override automatic mappings when column names differ or when you need to skip certain columns.

### Data type handling

Understand how the console handles data type conversions and what to do when types do not match.

## Best practices

- Validate CSV files before uploading to catch formatting errors early
- Start with a small sample file to verify mappings before importing large datasets
- Create the target table schema in advance for better control over data types
- Use consistent date and timestamp formats throughout your data
- Remove or handle null values appropriately based on your table constraints
- Back up existing table data before importing if you are appending to existing tables

## Troubleshooting

### Upload fails or times out

For large files, consider splitting into smaller chunks or using terminal-based import methods.

### Column mapping errors

Verify that column headers in your CSV exactly match the expected table column names, including case sensitivity.

### Data type mismatches

Check that values in each column are compatible with the target column data type. Common issues include dates in unexpected formats or numeric values containing text.

### Null value constraint violations

If your table has NOT NULL constraints, ensure your CSV contains valid data for those columns or adjust import settings for null handling.

### Encoding errors

Save your CSV file with UTF-8 encoding to prevent character corruption during import.
