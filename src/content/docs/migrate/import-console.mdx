This guide walks you through uploading CSV, Parquet, and text files into your {C.SERVICE_LONG} using [{C.CONSOLE}](https://console.cloud.tigerdata.com/dashboard/services). The {C.CONSOLE_SHORT} has **three upload formats**: **From CSV**, **From Parquet**, and **From a text file**. Pick the one that matches your file type, then follow the steps, you can upload from your local machine or from an S3 bucket, with no command-line tools required. You’ll map columns to your table schema, set format options (for example, delimiter, headers), and monitor import progress in the same interface.

## Before you start

### Prerequisites

To follow the steps on this page:

- Create a [{C.SERVICE_LONG}](/get-started/create-service/).
- Prepare data files in a supported format (CSV, TSV, Parquet, or text).
- Prepare a target table with the right schema, or plan to create one during the import.

### File types in {C.CONSOLE_SHORT}

In the upload flow, {C.CONSOLE} accepts three formats:

- **From CSV**: For comma- or delimiter-separated files (CSV, TSV). You can set delimiter, header row, and null handling.
- **From Parquet**: For Parquet files. The {C.CONSOLE_SHORT} infers schema and lets you map columns to your table.
- **From a text file**: For other text-based formats. Configure delimiter and parsing options as needed.

### Supported file formats and limits

- **CSV / TSV:** UTF-8 encoding recommended. Use a consistent delimiter; the first row can be headers. Fields with commas or special characters should be in double quotes. Files must be within the {C.CONSOLE_SHORT} upload size limits, for very large files, use [import via terminal](/migrate/import-terminal) or [sync from S3](/migrate/livesync-for-s3).
- **Parquet:** Supported for upload; follow the same mapping and validation steps. Schema is inferred from the file.
- **Text file:** Supported for other text formats; set delimiter and options in the {C.CONSOLE_SHORT}.

Validate your file (encoding, headers, delimiter) before uploading. Test with a small sample to confirm column mapping, then run the full import.

## How to upload a file

Follow these steps in {C.CONSOLE} to import a file into your {C.SERVICE_SHORT}.

<NumberedList>

<NumberedItem title={`Open your ${C.SERVICE_SHORT} and go to import`}>
In [{C.CONSOLE}](https://console.cloud.tigerdata.com/dashboard/services), select the {C.SERVICE_SHORT} you want to load data into, then click `Actions` > `Import data`.
</NumberedItem>

<NumberedItem title="Choose the file type">
Click `Upload your files` and select `CSV`, `Parquet`, or `Text`. The steps that follow depend on this choice (for example, CSV and text let you set delimiter and header; Parquet infers schema from the file).
</NumberedItem>

<NumberedItem title="Choose where the file comes from">
Select **Upload from your computer** for a local file, or **Import from S3** if the file is in an S3 bucket. If using S3, provide bucket and path (and credentials if required).
</NumberedItem>

<NumberedItem title="Select or create the target table">
Choose an existing table to receive the data, or create a new table. If you create a new table, define column names and types to match your file or let the {C.CONSOLE_SHORT} suggest a schema from the file.
</NumberedItem>

<NumberedItem title="Upload the file and set import options">
Upload your file (or confirm the S3 path), then set:
- **Delimiter** (for example, comma, tab) if using CSV/TSV.
- **Header row:** whether the first row is column headers.
- **Null value handling** (how empty or placeholder values are stored).
</NumberedItem>

<NumberedItem title="Map columns">
Review the mapping between file columns and table columns. The {C.CONSOLE_SHORT} tries to match by name; adjust or override as needed and ensure data types are compatible.
</NumberedItem>

<NumberedItem title="Preview and run the import">
Preview a sample of the data to catch formatting or mapping issues, then start the import. Monitor progress in the {C.CONSOLE_SHORT} until it completes.
</NumberedItem>

</NumberedList>

Your data is now imported into your {C.SERVICE_LONG}.

## Column mapping tips

- **Automatic mapping:** The {C.CONSOLE_SHORT} matches file headers to table columns by name. Always review before importing.
- **Manual adjustments:** Change mappings when names differ or when you want to skip columns.
- **Data types:** If the {C.CONSOLE_SHORT} warns about type mismatches, fix the file (for example, date format, numbers as text) or adjust the target column type.

## Troubleshooting

- **Upload fails or times out:** Use a smaller file or split the data; for large or automated loads, [import via terminal](/migrate/import-terminal).
- **Column mapping errors:** Ensure headers match the expected table columns (including case).
- **Data type or null errors:** Check that values fit the column types and that NOT NULL columns have no empty values, or adjust null handling in the import settings.
- **Encoding issues:** Save the file as UTF-8 to avoid corrupted characters.
