Time-series data accumulates rapidly and the value of older data typically decreases over time. To control storage
costs without losing access to historical data, you can move older {C.CHUNK}s from local storage to lower-cost object
storage while keeping them fully queryable through the same {C.HYPERTABLE}.

With {C.TIMESCALE_DB}, you can manually tier individual {C.CHUNK}s or implement automated policies using these APIs.

For more information about working with tiered data, see the [tiered storage section](/build/data-management/example-tiered-storage).

## Samples

### Create a tiering policy to move chunks older than 3 weeks to object storage

```sql
SELECT add_tiering_policy('assets_candlestick_daily', INTERVAL '3 weeks');
```

When you call `add_tiering_policy`, {C.CHUNK}s fully older than the supplied interval are frozen and queued for upload
to object storage in the background.

### Create a tiering policy with an integer-based time column

```sql
SELECT add_tiering_policy('events', BIGINT '1000000');
```

### Manually tier an individual chunk

```sql
SELECT tier_chunk('_timescaledb_internal._hyper_1_1_chunk');
```

### Bring a tiered chunk back into local storage

```sql
CALL untier_chunk('_hyper_1_1_chunk');
```

### Remove a tiering policy

```sql
SELECT remove_tiering_policy('assets_candlestick_daily');
```

Removes the existing tiering policy from the `assets_candlestick_daily` {C.HYPERTABLE}. {C.CHUNK}s already uploaded to
object storage remain tiered.

## Available functions

- [`add_tiering_policy()`](/reference/timescaledb/data-tiering/add_tiering_policy): create a policy to tier {C.CHUNK}s older than a given interval
- [`remove_tiering_policy()`](/reference/timescaledb/data-tiering/remove_tiering_policy): remove the tiering policy from a {C.HYPERTABLE} or {C.CAGG}
- [`tier_chunk()`](/reference/timescaledb/data-tiering/tier_chunk): manually tier an individual {C.CHUNK} to object storage
- [`untier_chunk()`](/reference/timescaledb/data-tiering/untier_chunk): move a tiered {C.CHUNK} back to local storage
- [`disable_tiering()`](/reference/timescaledb/data-tiering/disable_tiering): disable tiering on a {C.HYPERTABLE} and remove its OSM catalog entries
