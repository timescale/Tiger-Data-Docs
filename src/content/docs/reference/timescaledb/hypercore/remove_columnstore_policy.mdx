Remove a {C.COLUMNSTORE} policy from a {C.HYPERTABLE} or {C.CAGG}.

To restart automatic {C.CHUNK} migration to the {C.COLUMNSTORE}, you need to call
[add\_columnstore\_policy][add_columnstore_policy] again.

## Samples

You see the {C.COLUMNSTORE} policies in the [informational views][informational-views].

- **Remove the {C.COLUMNSTORE} policy from the `cpu` table**:

  ```sql
  CALL remove_columnstore_policy('cpu');
  ```

- **Remove the {C.COLUMNSTORE} policy from the `cpu_weekly` {C.CAGG}**:

  ```sql
  CALL remove_columnstore_policy('cpu_weekly');
  ```

## Arguments

The syntax is:

```sql
CALL remove_columnstore_policy(
    hypertable = '<hypertable_name>',
    if_exists = true | false
);
```

| Name | Type | Default | Required | Description |
|--|--|--|--|-|
|`hypertable`|REGCLASS|-|✔| Name of the {C.HYPERTABLE} or {C.CAGG} to remove the policy from|
| `if_exists` | BOOLEAN | `false` |✖| Set to `true` so this job fails with a warning rather than an error if a {C.COLUMNSTORE} policy does not exist on `hypertable` |
