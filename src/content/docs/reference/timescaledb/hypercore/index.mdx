## Samples

Best practice for using {C.HYPERCORE} is to:

1. **Enable {C.COLUMNSTORE} on a {C.HYPERTABLE}**

   For [efficient queries](/build/performance-optimization/secondary-indexes), remember to `segmentby` the column you will
   use most often to filter your data. For example:

   - **{C.HYPERTABLE_CAP}s**:

     Use [`CREATE TABLE`](/reference/timescaledb/hypertables/create_table):

     ```sql
     CREATE TABLE crypto_ticks (
       "time" TIMESTAMPTZ,
       symbol TEXT,
       price DOUBLE PRECISION,
       day_volume NUMERIC
     ) WITH (
       timescaledb.hypertable,
       timescaledb.segmentby='symbol',
       timescaledb.orderby='time DESC'
     );
     ```

     <OldCreateHypertable />
   - **{C.CAGG_CAP}s**:

   1. [Use `ALTER MATERIALIZED VIEW` for a {C.CAGG}](/reference/timescaledb/continuous-aggregates/alter_materialized_view):
      ```sql
      ALTER MATERIALIZED VIEW assets_candlestick_daily set (
         timescaledb.enable_columnstore = true,
         timescaledb.segmentby = 'symbol');
      ```

   2. Create a [columnstore\_policy](/reference/timescaledb/hypercore/add_columnstore_policy) that automatically converts {C.CHUNK}s in a {C.HYPERTABLE}
      to the {C.COLUMNSTORE} at a specific time interval. For example:
      ```sql
      CALL add_columnstore_policy('assets_candlestick_daily', after => INTERVAL '1d');
      ```

   {C.TIMESCALE_DB} is optimized for fast updates on compressed data in the {C.COLUMNSTORE}. To modify data in the
   {C.COLUMNSTORE}, use standard SQL.

2. **View the policies that you set or the policies that already exist**

   ```sql
   SELECT * FROM timescaledb_information.jobs
   WHERE proc_name='policy_compression';
   ```

   See [timescaledb\_information.jobs](/reference/timescaledb/informational-views/jobs).

You can also [convert\_to\_columnstore](/reference/timescaledb/hypercore/convert_to_columnstore) and [convert\_to\_rowstore](/reference/timescaledb/hypercore/convert_to_rowstore) manually
for more fine-grained control over your data.

## Limitations

{C.CHUNK}s in the {C.COLUMNSTORE} have the following limitations:

- `ROW LEVEL SECURITY` is not supported on {C.CHUNK}s in the {C.COLUMNSTORE}.

## Available functions

### Policies

- [`add_columnstore_policy()`](/reference/timescaledb/hypercore/add_columnstore_policy): set a policy to automatically move {C.CHUNK}s in a {C.HYPERTABLE}
  to the {C.COLUMNSTORE} when they reach a given age
- [`remove_columnstore_policy()`](/reference/timescaledb/hypercore/remove_columnstore_policy): remove a {C.COLUMNSTORE} policy from a {C.HYPERTABLE}

### Configuration

- [`ALTER TABLE (hypercore)`](/reference/timescaledb/hypercore/alter_table): enable the {C.COLUMNSTORE} for a {C.HYPERTABLE}

### Manual conversion

- [`convert_to_columnstore()`](/reference/timescaledb/hypercore/convert_to_columnstore): manually add a {C.CHUNK} to the {C.COLUMNSTORE}
- [`convert_to_rowstore()`](/reference/timescaledb/hypercore/convert_to_rowstore): move a {C.CHUNK} from the {C.COLUMNSTORE} to the {C.ROWSTORE}

### Statistics and information

- [`chunk_columnstore_stats()`](/reference/timescaledb/hypercore/chunk_columnstore_stats): get statistics about {C.CHUNK}s in the {C.COLUMNSTORE}
- [`hypertable_columnstore_stats()`](/reference/timescaledb/hypercore/hypertable_columnstore_stats): get {C.COLUMNSTORE} statistics related to the

{C.COLUMNSTORE}

- [`timescaledb_information.chunk_columnstore_settings`](/reference/timescaledb/hypercore/chunk_columnstore_settings): get information about settings on
  each {C.CHUNK} in the {C.COLUMNSTORE}
- [`timescaledb_information.hypertable_columnstore_settings`](/reference/timescaledb/hypercore/hypertable_columnstore_settings): get information about
  {C.COLUMNSTORE} settings for all {C.HYPERTABLE}s
