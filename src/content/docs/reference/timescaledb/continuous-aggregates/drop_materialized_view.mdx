{C.CAGG_CAP} views can be dropped using the `DROP MATERIALIZED VIEW` statement.

This statement deletes the {C.CAGG} and all its internal
objects. It also removes refresh policies for that
aggregate. To delete other dependent objects, such as a view
defined on the {C.CAGG}, add the `CASCADE`
option. Dropping a {C.CAGG} does not affect the data in
the underlying {C.HYPERTABLE} from which the {C.CAGG} is
derived.

```sql
DROP MATERIALIZED VIEW <view_name>;
```

## Samples

Drop existing {C.CAGG}.

```sql
DROP MATERIALIZED VIEW contagg_view;
```

## Arguments

The syntax is:

```sql
DROP MATERIALIZED VIEW [IF EXISTS] <view_name>;
```

| Name | Type | Default | Required | Description |
|-|-|-|-|-|
| `<view_name>` | TEXT | - | ✔ | Name (optionally schema-qualified) of {C.CAGG} view to be dropped. |

## Returns

For standard `DROP MATERIALIZED VIEW` return behavior, see the [{C.PG} DROP MATERIALIZED VIEW documentation](https://www.postgresql.org/docs/current/sql-dropmaterializedview.html).
