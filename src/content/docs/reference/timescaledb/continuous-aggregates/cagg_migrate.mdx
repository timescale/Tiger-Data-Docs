Migrate a {C.CAGG} from the old format to the new format introduced
in {C.TIMESCALE_DB} 2.7.

```sql
CALL cagg_migrate (
    cagg REGCLASS,
    override BOOLEAN DEFAULT FALSE,
    drop_old BOOLEAN DEFAULT FALSE
);
```

{C.TIMESCALE_DB} 2.7 introduced a new format for {C.CAGG}s that improves
performance. It also makes {C.CAGG}s compatible with more types of
SQL queries.

The new format, also called the finalized format, stores the {C.CAGG} data exactly as it appears in the final view. The
old format, also
called the partial format, stores the data in a partially aggregated state.

Use this procedure to migrate {C.CAGG}s from the old format to the
new format.

For more information, see the [migration how-to guide](/build/continuous-aggregates/migrate-to-new-form).

<Callout variant="warning">
  There are known issues with `cagg_migrate()` in version {C.TIMESCALE_DB} 2.8.0.
  Upgrade to version 2.8.1 or above before using it.
</Callout>

## Arguments

The syntax is:

```sql
CALL cagg_migrate(
    cagg = '<view_name>',
    override = true | false,
    drop_old = true | false
);
```

| Name | Type | Default | Required | Description |
|-|-|-|-|-|
| `cagg` | `REGCLASS` | - | ✔ | The {C.CAGG} to migrate |
| `override` | `BOOLEAN` | `false` | - | If false, the old {C.CAGG} keeps its name. The new {C.CAGG} is named `<OLD_CONTINUOUS_AGGREGATE_NAME>_new`. If true, the new {C.CAGG} gets the old name. The old {C.CAGG} is renamed `<OLD_CONTINUOUS_AGGREGATE_NAME>_old`. |
| `drop_old` | `BOOLEAN` | `false` | - | If true, the old {C.CAGG} is deleted. Must be used together with `override`. |
