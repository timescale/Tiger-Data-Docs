TimescaleDB allows you to move data and indexes to different tablespaces. This
allows you to move data to more cost-effective storage as it ages.

The `move_chunk` function acts like a combination of the
[{C.PG} CLUSTER command](https://www.postgresql.org/docs/current/sql-cluster.html) and
[{C.PG} ALTER TABLE...SET TABLESPACE](https://www.postgresql.org/docs/13/sql-altertable.html) commands. Unlike
these {C.PG} commands, however, the `move_chunk` function uses lower lock
levels so that the {C.CHUNK} and {C.HYPERTABLE} are able to be read for most of the
process. This comes at a cost of slightly higher disk usage during the
operation. For a more detailed discussion of this capability, see the
documentation on [managing storage with tablespaces](/build/performance-optimization/manage-tablespaces).

<Callout variant="important">
  You must be logged in as a super user, such as the `postgres` user,
  to use the `move_chunk()` call.
</Callout>

## Samples

```sql
SELECT move_chunk(
  chunk => '_timescaledb_internal._hyper_1_4_chunk',
  destination_tablespace => 'tablespace_2',
  index_destination_tablespace => 'tablespace_3',
  reorder_index => 'conditions_device_id_time_idx',
  verbose => TRUE
);
```

## Arguments

The syntax is:

```sql
SELECT move_chunk(
    chunk = '<chunk_name>',
    destination_tablespace = '<tablespace_name>',
    index_destination_tablespace = '<tablespace_name>',
    reorder_index = '<index_name>',
    verbose = true | false
);
```

|Name|Type| Default | Required | Description|
|-|-|-|-|-|
|`chunk`|REGCLASS| - | ✔ |Name of {C.CHUNK} to be moved|
|`destination_tablespace`|NAME| - | ✔ |Target tablespace for {C.CHUNK} being moved|
|`index_destination_tablespace`|NAME| `NULL` | ✖ |Target tablespace for index associated with the {C.CHUNK} you are moving|
|`reorder_index`|REGCLASS| - | ✖ |The name of the index (on either the {C.HYPERTABLE} or {C.CHUNK}) to order by|
|`verbose`|BOOLEAN| `FALSE` | ✖ |Setting to true displays messages about the progress of the move\_chunk command.|

## Returns

This function returns void.
