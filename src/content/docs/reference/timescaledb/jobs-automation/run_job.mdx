Run a previously registered {C.JOB} in the current session.
This works for {C.JOB} as well as policies.
Since `run_job` is implemented as stored procedure it cannot be executed
inside a SELECT query but has to be executed with `CALL`.

<Callout variant="note">
  Any background worker {C.JOB} can be run in the foreground when executed with
  `run_job`. You can use this with an increased log level to help debug problems.
</Callout>

## Samples

Set log level shown to client to `DEBUG1` and run the {C.JOB} with the {C.JOB} ID 1000:

```sql
SET client_min_messages TO DEBUG1;
CALL run_job(1000);
```

## Arguments

The syntax is:

```sql
CALL run_job(
    job_id = <job_id>
);
```

| Name | Type | Default | Required | Description |
|---|---|---|---|---|
| `job_id` | INTEGER | - | ✔ | TimescaleDB background {C.JOB} ID |
