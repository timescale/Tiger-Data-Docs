## Overview

This guide covers how to upgrade your self-hosted TimescaleDB installation, including updating the TimescaleDB extension and upgrading the underlying PostgreSQL version. Upgrades are performed in-place using PostgreSQL's ALTER EXTENSION support.

## Prerequisites

- A running self-hosted TimescaleDB installation
- Superuser privileges on the database
- A recent backup of your database
- If using TimescaleDB Toolkit, ensure it is version 1.6.0 or higher before upgrading

## Before you upgrade

### Create a backup

Upgrading is an intrusive operation. Always create a backup before proceeding and verify the backup is readable.

### Check current versions

Verify your current TimescaleDB and PostgreSQL versions before upgrading.

```sql
SELECT default_version, installed_version
FROM pg_available_extensions
WHERE name = 'timescaledb';
```

### Review version compatibility

Check that your target TimescaleDB version is compatible with your PostgreSQL version.

## Update the TimescaleDB extension

### Step 1: install the new TimescaleDB version

Update the TimescaleDB package using your system's package manager (apt, yum, brew) or build from source.

### Step 2: run ALTER EXTENSION

Connect to each database using TimescaleDB and run the upgrade command.

```sql
ALTER EXTENSION timescaledb UPDATE;
```

### Step 3: verify the upgrade

Confirm the extension has been updated to the new version.

### Handling loader version errors

If you see "loader version out-of-date" errors, restart PostgreSQL and retry the ALTER EXTENSION command.

## Upgrade PostgreSQL version

When upgrading the PostgreSQL major version (for example, from 15 to 16), you have two options.

### Option 1: using pg_upgrade

Use PostgreSQL's pg_upgrade utility for in-place major version upgrades.

### Option 2: backup and restore

Create a backup from the old version and restore into a fresh installation of the new version.

## Multi-database environments

TimescaleDB supports different extension versions on different databases within the same PostgreSQL instance. Run ALTER EXTENSION on each database individually to upgrade them.
