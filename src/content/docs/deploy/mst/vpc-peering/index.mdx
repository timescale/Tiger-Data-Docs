Virtual Private Cloud (VPC) peering is a method of connecting separate Cloud
private networks to each other. It makes it possible for the virtual machines in
the different VPCs to talk to each other directly without going through the
public internet. VPC peering is limited to VPCs that share the same Cloud
provider.

VPC peering setup is a per project and per region setting. This means that all
{C.MST_SERVICE_SHORT}s created and running utilize the same VPC peering connection. If needed,
you can have multiple projects that peer with different connections.

<Callout variant="note">

{C.MST_SERVICE_LONG}s are only accessible using your VPC's internal network. They are not
accessible from the public internet. TLS certificates for VPC peered {C.MST_SERVICE_SHORT}s are
signed by the {C.MST_SHORT} project CA and cannot be validated against a public CA
(Let's Encrypt). You can choose whether you want to run on a VPC
peered network or on the public internet for every {C.MST_SERVICE_SHORT}.

</Callout>

You can set up VPC peering on:

*   [Amazon Web Services (AWS)](/deploy/mst/vpc-peering/vpc-peering-aws)
*   [Google Cloud Platform (GCP)](/deploy/mst/vpc-peering/vpc-peering-gcp)
*   [Microsoft Azure](/deploy/mst/vpc-peering/vpc-peering-azure)
