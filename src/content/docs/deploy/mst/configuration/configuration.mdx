## Overview

Configure your Managed Service for TimescaleDB (MST) instance to optimize performance, resource allocation, and database behavior. This guide covers runtime parameters, TimescaleDB-specific settings, and best practices for tuning your managed database.

## Prerequisites

- An active MST instance
- Admin or appropriate role permissions to modify configuration
- Understanding of your workload characteristics (OLTP, analytics, or mixed)

## Runtime configuration parameters

Manage PostgreSQL and TimescaleDB runtime parameters through the Tiger Cloud console or API.

### Viewing current configuration

How to view and export your current configuration settings.

### Modifying parameters

Steps to modify configuration parameters, including which changes require a restart versus those that take effect immediately.

### Common PostgreSQL parameters

Key PostgreSQL parameters to consider:
- `shared_buffers` - Memory for caching data
- `work_mem` - Memory for query operations
- `maintenance_work_mem` - Memory for maintenance operations
- `effective_cache_size` - Planner's assumption about disk caching
- `max_connections` - Maximum concurrent connections

## TimescaleDB-specific configuration

Settings unique to TimescaleDB that affect hypertable performance and background operations.

### Background workers

Configure `timescaledb.max_background_workers` to control parallel operations for compression, retention policies, and continuous aggregate refresh.

### Chunk configuration

Settings that affect chunk creation and management, including chunk time intervals and chunk sizing recommendations based on your data volume.

### Compression settings

Configure compression behavior, including compression algorithms and segmentby/orderby parameters for optimal query performance on compressed data.
