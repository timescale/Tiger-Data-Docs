The `dblink` [{C.PG} extension](https://www.postgresql.org/docs/current/dblink.html) allows you to connect to
other {C.PG} databases and to run arbitrary queries.

You can use [foreign data wrappers](https://www.postgresql.org/docs/current/postgres-fdw.html) (FDWs) to define a remote
`foreign server` to access its data. The database connection details such as
hostnames are kept in a single place, and you only need to create a
`user mapping` to store remote connections credentials.

## Before you begin

Sign in to your {C.MST_SERVICE_LONG},
navigate to the `Overview` tab, and take a note of these parameters for the
{C.PG} remote server. Alternatively, you can use the `avn service get`
command in the Aiven client:

*   `HOSTNAME`: The remote database hostname
*   `PORT`: The remote database port
*   `USER`: The remote database user to connect. The default user is `tsdbadmin`.
*   `PASSWORD`: The remote database password for the `USER`
*   `DATABASE_NAME`: The remote database name. The default database name is `defaultdb`.

## Enable the dblink extension

To enable the `dblink` extension on an {C.MST_SHORT} {C.PG} {C.MST_SERVICE_SHORT}:

<NumberedList>

<NumberedItem title="Connect to the database">

Connect to the database as the `tsdbadmin` user:

```bash
psql -x "postgres://tsdbadmin:<PASSWORD>@<HOSTNAME>:<PORT>/defaultdb?sslmode=require"
```

</NumberedItem>

<NumberedItem title="Create the dblink extension and test data">

<ol type="a">
<li>

Create the `dblink` extension:

```sql
CREATE EXTENSION dblink;
```

</li>
<li>

Create a table named `inventory`:

```sql
CREATE TABLE inventory (id int);
```

</li>
<li>

Insert data into the `inventory` table:

```sql
INSERT INTO inventory (id) VALUES (100), (200), (300);
```

</li>
</ol>

</NumberedItem>

</NumberedList>

## Create a foreign data wrapper using dblink_fdw

<NumberedList>

<NumberedItem title="Create a user">

Create a user `user1` who can access the `dblink`:

```sql
CREATE USER user1 PASSWORD 'secret1'
```

</NumberedItem>

<NumberedItem title="Create a remote server definition">

Create a remote server definition named `mst_remote`, using `dblink_fdw` and
the connection details of the {C.MST_SERVICE_LONG}:

```sql
CREATE SERVER mst_remote
    FOREIGN DATA WRAPPER dblink_fdw
    OPTIONS (
             host 'HOST',
             dbname 'DATABASE_NAME',
             port 'PORT'
             );
```

</NumberedItem>

<NumberedItem title="Create a user mapping">

Create a user mapping for `user1` to automatically authenticate as
`tsdbadmin` when using the `dblink`:

```sql
CREATE USER MAPPING FOR user1
   SERVER mst_remote
   OPTIONS (
    user 'tsdbadmin',
    password 'PASSWORD'
    );
```

</NumberedItem>

<NumberedItem title="Grant usage on the remote server">

Enable `user1` to use the remote {C.PG} connection `mst_remote`:

```sql
GRANT USAGE ON FOREIGN SERVER mst_remote TO user1;
```

</NumberedItem>

</NumberedList>

## Query data using a foreign data wrapper

To query a foreign data wrapper, you must be a database user with the necessary
permissions on the remote server.

<NumberedList>

<NumberedItem title="Connect to the service">

Connect to the {C.MST_SERVICE_LONG} as `user1` with necessary grants to the remote server.

</NumberedItem>

<NumberedItem title="Establish the dblink connection">

Establish the `dblink` connection to the remote target server:

```sql
SELECT dblink_connect('my_new_conn', 'mst_remote');
```

</NumberedItem>

<NumberedItem title="Query using the foreign server definition">

Query using the foreign server definition as parameter:

```sql
SELECT * FROM dblink('my_new_conn','SELECT * FROM inventory') AS t(a int);
```

Output is similar to:

```sql
    a
  -----
   100
   200
   300
 (3 rows)
```

</NumberedItem>

</NumberedList>
