## Overview

Secure your Managed Service for TimescaleDB (MST) instance with authentication, authorization, and network controls. This guide covers how to configure access controls that protect your data while enabling authorized users and applications to connect.

## Prerequisites

- An active MST instance
- Admin permissions in the Tiger Cloud console
- Understanding of your application's connection requirements

## Authentication

Control who can connect to your database.

### Password authentication

MST uses SCRAM-SHA-256 for password authentication, the most secure password-based method available in {C.PG}.

- Creating and managing database users
- Password policies and rotation
- Storing credentials securely in applications

### SSL/TLS connections

All connections to MST are encrypted using TLS by default.

- Certificate verification modes
- Downloading CA certificates
- Configuring client applications for TLS

### Service accounts

Create dedicated credentials for applications and services.

- Application-specific database users
- Principle of least privilege for service accounts
- Credential rotation strategies

## Authorization

Control what authenticated users can do.

### Role-based access control (RBAC)

{C.PG}'s role system provides granular permission management.

- Creating roles for different access levels
- Granting permissions on databases, schemas, and tables
- Using role inheritance for permission hierarchies
- Predefined roles (read-only, read-write, admin)

### Row-level security (RLS)

Implement fine-grained access control at the row level.

- Enabling RLS on tables
- Creating security policies
- Use cases: multi-tenant applications, data isolation

### Schema and object permissions

Control access to specific database objects.

- Schema-level permissions
- Table and view permissions
- Function and procedure permissions

## Network security

Control where connections can originate from.

### IP allowlisting

Restrict database access to specific IP addresses or CIDR ranges.

- Adding allowed IP addresses
- Managing IP allowlist rules
- Best practices for allowlist management

### VPC peering

Connect your MST instance to your private cloud network.

- Setting up VPC peering
- Supported cloud providers and regions
- Routing configuration

### Private endpoints

Access your database without traversing the public internet.

- Creating private endpoints
- DNS configuration
- Benefits for compliance and security

## Connection security best practices

Recommendations for secure database connectivity.

### Application connections

- Use connection pooling to reduce connection overhead
- Store credentials in secrets managers, not code
- Implement connection retry logic with exponential backoff
- Use read replicas to distribute load

### Administrative access

- Use separate admin accounts from application accounts
- Enable audit logging for administrative actions
- Consider jump hosts or bastion servers for admin access
- Implement multi-factor authentication where possible

## Auditing and monitoring

Track and review database access.

### Connection logging

Monitor who connects to your database and when.

### Query auditing

Log queries for compliance and security analysis using pgAudit.

### Failed authentication attempts

Alert on repeated failed login attempts that may indicate attacks.

## Troubleshooting

Common access issues and solutions.

- Connection refused errors
- SSL certificate verification failures
- Permission denied errors
- IP not in allowlist
