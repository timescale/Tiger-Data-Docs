## Overview

Tiger Cloud read replicas allow you to scale read operations horizontally by distributing query load across multiple nodes. This enables your applications to handle increased read traffic while keeping write operations on the primary instance. Read replicas can deliver up to linear performance improvements as you add nodes to your cluster.

## Prerequisites

- A Tiger Cloud database instance (primary)
- Understanding of your application's read/write patterns
- Network configuration that supports replica connections
- Sufficient compute and storage quotas for additional replicas

## Best practices

- Place read replicas in different availability zones from the primary
- Scale storage on replicas before scaling the primary
- Avoid creating replicas during high transactional load or bulk migrations
- Monitor replication lag and configure alerts for your acceptable threshold
- Use connection pooling to efficiently manage replica connections

## Limitations

- Read replicas are read-only and cannot accept write operations
- Read replicas do not reduce write bottlenecks on the primary
- Some replication lag is inherent in asynchronous replication
