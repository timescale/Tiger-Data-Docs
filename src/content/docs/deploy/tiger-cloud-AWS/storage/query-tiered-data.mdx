## Overview

Tiger Cloud enables you to query data across both high-performance and low-cost storage tiers using standard SQL. This guide explains how to write efficient queries against tiered data and optimize performance for different workloads.

## Prerequisites

- An active Tiger Cloud service with tiered storage configured
- Data distributed across both storage tiers
- Basic familiarity with SQL and time-series queries

## How tiered queries work

This section explains the mechanics of querying across storage tiers.

### Transparent data access

How Tiger Cloud seamlessly queries data regardless of which tier it resides in:
- Query planner automatically identifies relevant chunks
- Data is fetched from the appropriate tier
- Results are combined transparently

### Query performance optimizations

Built-in optimizations that accelerate tiered data queries:
- Chunk exclusion based on time predicates
- Row-group exclusion within Parquet files
- Column exclusion for selective queries

## Write efficient queries

Best practices for querying tiered data with optimal performance.

### Use time-based filters

How to leverage time predicates to minimize data scanned:
- Always include WHERE clauses on the time column
- Use appropriate time ranges to target specific tiers
- Leverage chunk exclusion for faster queries

### Optimize SELECT clauses

Reduce I/O by selecting only necessary columns:
- Avoid SELECT * when possible
- Column exclusion benefits for wide tables
- Impact on query latency

### Use LIMIT and ORDER BY

Strategies for retrieving partial results efficiently:
- Combining LIMIT with ORDER BY for top-N queries
- Reducing overhead when scanning large datasets
