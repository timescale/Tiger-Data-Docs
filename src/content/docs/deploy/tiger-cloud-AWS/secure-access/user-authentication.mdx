## Overview

This guide explains the authentication methods available in Tiger Cloud and how to configure them for secure database access. You will learn about password-based authentication, best practices for credential management, and how to implement strong authentication for your users.

## Prerequisites

- An active Tiger Cloud service
- Administrative access to your database
- Understanding of your security requirements
- Client applications that support modern authentication methods

## Authentication methods

Tiger Cloud supports several {C.PG} authentication methods.

### SCRAM-SHA-256 (recommended)

SCRAM-SHA-256 is the recommended authentication method for Tiger Cloud. It uses a challenge-response mechanism that:

- Never sends passwords in clear text over the network
- Stores password hashes in a cryptographically secure format
- Protects against replay attacks
- Prevents hash theft from compromising passwords

### MD5 (deprecated)

MD5 authentication is deprecated and should not be used for new deployments. If you have existing users using MD5, plan to migrate them to SCRAM-SHA-256.

### Certificate authentication

SSL certificate authentication allows users to authenticate using a client certificate instead of a password. This method:

- Eliminates password management overhead
- Provides strong cryptographic authentication
- Requires a PKI infrastructure to manage certificates

## Migrating from MD5 to SCRAM-SHA-256

If you have existing users with MD5 authentication, follow these steps to migrate.

### Step 1: verify client compatibility

Ensure all client applications support SCRAM-SHA-256 authentication. Minimum version requirements:

- psycopg2: 2.8+
- node-postgres: 8.0+
- JDBC: 42.2.0+
- Other drivers: Check documentation

### Step 2: update server configuration

How to configure the server for SCRAM-SHA-256.

### Step 3: update user passwords

Users must set new passwords after changing the encryption method, as {C.PG} cannot convert existing MD5 hashes.

### Step 4: verify migration

How to confirm users are now using SCRAM-SHA-256.

## Application authentication best practices

Recommendations for how applications should authenticate to the database.

### Use dedicated service accounts

Create separate database users for each application rather than sharing credentials.

### Secure credential storage

Options for storing database credentials securely:

- Environment variables
- Secrets management systems (HashiCorp Vault, AWS Secrets Manager, etc.)
- Kubernetes secrets
- Avoid hardcoding credentials in application code

### Connection string security

Protect connection strings from exposure:

- Do not log connection strings
- Use secure channels to transmit credentials
- Rotate credentials regularly
