## Overview

This guide explains how to configure an IP allow list for your Tiger Cloud service. An IP allow list restricts database access to specific IP addresses or CIDR ranges, providing an additional layer of security by blocking connection attempts from unauthorized networks.

## Prerequisites

- An active Tiger Cloud service
- Administrative access to your Tiger Cloud project
- Knowledge of the IP addresses or CIDR ranges that need database access
- Static IP addresses for your application servers (recommended)

## How IP allow lists work

IP allow lists operate as a network-level firewall rule that filters incoming connection requests based on the source IP address. Only connections originating from IP addresses on your allow list can reach your database.

### Security benefits

- Reduces attack surface by blocking unauthorized networks
- Provides defense-in-depth when combined with authentication
- Prevents brute-force attacks from unknown IP addresses
- Helps meet compliance requirements for network access control

### Limitations to consider

- Not suitable as the sole security measure
- Requires static IP addresses for allowed sources
- May complicate access for remote workers with dynamic IPs
- Does not protect against attacks from allowed IP addresses

## Best practices

Recommendations for managing your IP allow list effectively.

### Use descriptive labels

Give each entry a clear name that identifies its purpose (e.g., "Production API servers" or "CI/CD pipeline").

### Prefer CIDR ranges over individual IPs

When possible, use CIDR notation to reduce the number of entries and simplify management.

### Avoid overly broad ranges

Do not allow entire ISP ranges or public cloud regions. Be as specific as possible.

### Regular audits

Review your allow list periodically to remove stale entries and verify all entries are still needed.

### Document your entries

Maintain documentation about why each entry exists and who is responsible for it.

### Combine with other security measures

Use IP allow lists as part of a defense-in-depth strategy that includes:

- Strong authentication (SCRAM-SHA-256)
- SSL/TLS encryption
- Role-based access control
- Monitoring and alerting
