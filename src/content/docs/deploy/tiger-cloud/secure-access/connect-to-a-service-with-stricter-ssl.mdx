## Overview

This guide explains how to configure stricter SSL/TLS settings when connecting to Tiger Cloud. Stricter SSL modes like `verify-ca` and `verify-full` provide additional security by verifying the server's identity, protecting against man-in-the-middle attacks.

## Prerequisites

- An active Tiger Cloud service
- The Tiger Cloud root CA certificate
- A database client that supports SSL certificate verification
- Understanding of your security and compliance requirements

## Understanding SSL modes

PostgreSQL supports several SSL modes with increasing levels of security.

### SSL mode comparison

| Mode | Encryption | Server certificate verification | Hostname verification |
|------|------------|--------------------------------|----------------------|
| `disable` | No | No | No |
| `allow` | If available | No | No |
| `prefer` | If available | No | No |
| `require` | Yes | No | No |
| `verify-ca` | Yes | Yes | No |
| `verify-full` | Yes | Yes | Yes |

### When to use each mode

- **`require`**: Ensures encryption but does not verify the server identity. Suitable when you trust the network path.
- **`verify-ca`**: Verifies the server certificate is signed by a trusted CA. Use when you have a private CA.
- **`verify-full`**: Verifies the CA and that the hostname matches the certificate. Recommended for production environments.

## Configuring verify-full mode

### How hostname verification works

In `verify-full` mode, the client verifies that:

1. The server certificate is signed by a trusted CA
2. The hostname in the connection string matches either:
   - A Subject Alternative Name (SAN) in the certificate, or
   - The Common Name (CN) if no SAN is present

## Client certificate authentication (Mutual TLS)

For maximum security, configure mutual TLS where both server and client authenticate with certificates.

### How mutual TLS works

In mutual TLS (mTLS):

1. The server presents its certificate to the client
2. The client verifies the server certificate
3. The client presents its certificate to the server
4. The server verifies the client certificate and uses it for authentication

## TLS version requirements

### Recommended TLS versions

- TLS 1.3: Most secure, recommended where supported
- TLS 1.2: Widely supported, minimum recommended version
- TLS 1.1 and below: Deprecated, do not use
