## Overview

This guide explains how to establish secure connections to Tiger Cloud from any cloud provider, including Google Cloud Platform, Microsoft Azure, and other infrastructure providers. You will learn about the available connectivity options and how to implement encryption and network security across cloud boundaries.

## Prerequisites

- An active Tiger Cloud account with a deployed database service
- Administrative access to your cloud provider's networking configuration
- Understanding of your network topology and security requirements
- SSL/TLS certificates for encrypted connections (if using mutual TLS)

## Security best practices

Recommendations for securing multi-cloud database connections:

### Encryption in transit

- Always use SSL/TLS for database connections
- Configure minimum TLS version (TLS 1.2 or 1.3)
- Use strong cipher suites

### Network segmentation

- Isolate database traffic in dedicated subnets
- Implement microsegmentation to limit lateral movement
- Use network security groups to restrict access

### API security

- Secure any management APIs with authentication
- Encrypt API communications
- Monitor for anomalous API access patterns

### Data protection

- Encrypt data at rest and in transit
- Implement data loss prevention (DLP) controls
- Maintain regular backups across regions

## Connection pooling considerations

Best practices for managing database connections in multi-cloud environments:

- Pre-create minimum connection pools to reduce latency
- Set appropriate maximum pool sizes to avoid overloading the database
- Configure connection timeouts for cross-cloud latency

## Monitoring and observability

How to monitor your multi-cloud database connections:

- Track connection latency and throughput
- Set up alerts for connectivity failures
- Monitor network path changes

## Troubleshooting

Common issues and their solutions:

- High latency on cross-cloud connections
- Intermittent connectivity failures
- TLS handshake errors
- DNS resolution issues across cloud boundaries
- Firewall rules blocking database traffic
