## Overview

Tiger Cloud collects comprehensive telemetry data from your database services to enable monitoring, troubleshooting, and performance optimization. This guide explains the types of telemetry available, how data is collected, and how you can use it to gain insights into your services.

## Prerequisites

- An active Tiger Cloud service
- Access to the Tiger Cloud Console

## Telemetry types

Understanding the three pillars of observability data collected by Tiger Cloud.

### Metrics

Numeric measurements collected at regular intervals:

- Performance metrics (query latency, throughput)
- Resource utilization (CPU, memory, storage, network)
- Connection statistics
- Cache efficiency ratios
- Replication status and lag

### Logs

Structured and unstructured log data from your services:

- Query logs (including slow query logs)
- Connection and authentication logs
- Error and warning logs
- Audit logs for security events
- System event logs

### Traces

Distributed tracing data for request flow analysis:

- Query execution traces
- Connection lifecycle traces
- Cross-service correlation with OpenTelemetry

## Key metrics reference

Detailed reference of important telemetry metrics.

### Database performance

- `tiger_query_duration_seconds` - Query execution time histogram
- `tiger_queries_total` - Total query count by type
- `tiger_transactions_total` - Transaction commit and rollback counts

### Connections

- `tiger_connections_active` - Current active connections
- `tiger_connections_idle` - Idle connections in pool
- `tiger_connections_waiting` - Clients waiting for connections

### Resources

- `tiger_cpu_usage_percent` - CPU utilization
- `tiger_memory_usage_bytes` - Memory consumption
- `tiger_storage_used_bytes` - Storage utilization

### Replication

- `tiger_replication_lag_seconds` - Replication delay
- `tiger_wal_position` - Write-ahead log position

## Troubleshooting

Common issues with telemetry:

- Missing or gaps in telemetry data
- High telemetry volume impacting performance
- Export failures to external systems
- Incorrect metric values

## Best practices

- Use telemetry to establish performance baselines
- Correlate metrics, logs, and traces for comprehensive debugging
- Set appropriate retention periods based on your needs
- Export telemetry to external systems for long-term analysis
- Use OpenTelemetry for cross-service correlation in distributed systems
