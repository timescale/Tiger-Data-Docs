## Overview

Tiger Cloud alerting helps you proactively monitor your database services and receive notifications when metrics exceed defined thresholds. By setting up automated alerts, you can respond to potential issues before they impact your applications and users.

## Prerequisites

- An active Tiger Cloud service
- Access to the Tiger Cloud Console
- Notification channel configured (email, Slack, PagerDuty, or webhook)

## Recommended alert thresholds

Best practice threshold recommendations for common scenarios:

- **Connections**: Alert at 80% of max connections for 30+ minutes
- **CPU/Memory**: Alert at 95% utilization for 2+ hours or 100% for 5 minutes
- **Storage**: Alert at 80-95% depending on total capacity
- **Replication lag**: Alert when lag exceeds acceptable limits for your use case
- **Query latency**: Alert when p99 latency exceeds baseline thresholds

## Troubleshooting

Common issues and solutions:

- Alerts not firing when expected
- Too many false positive alerts
- Notification delivery failures
- Alert evaluation delays

## Best practices

- Focus on actionable metrics that directly impact performance
- Avoid alert fatigue by setting appropriate thresholds
- Use different severity levels for different conditions
- Regularly review and tune alert thresholds based on baseline data
- Combine multiple metrics for more accurate alerting
