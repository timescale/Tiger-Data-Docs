## Overview

This guide explains how to configure role-based access control (RBAC) in Tiger Cloud. RBAC allows you to define roles with specific permissions and assign those roles to database users, ensuring that each user has only the access they need to perform their tasks.

## Prerequisites

- An active Tiger Cloud service
- Administrative access to your database
- Understanding of your application's access requirements
- Familiarity with PostgreSQL roles and privileges

## Understanding PostgreSQL roles

PostgreSQL uses roles to manage database access. A role can represent a database user (with login capability) or a group of users (for organizing permissions).

### Key concepts

- **Roles**: The unified concept for users and groups in PostgreSQL
- **Privileges**: Specific permissions granted on database objects
- **Role membership**: Roles can be members of other roles, inheriting their privileges
- **Ownership**: Roles own the objects they create

Overview of the predefined roles available in Tiger Cloud:

- `tsdbadmin`: Administrative role with full privileges

## Planning your access control strategy

Before creating roles, plan your access requirements.

### Identify user groups

Common role categories to consider:

- **Administrators**: Full database management capabilities
- **Application users**: Read-write access to application data
- **Read-only users**: Query access for reporting and analytics
- **Schema managers**: DDL permissions for specific schemas
- **Backup operators**: Permissions for backup and restore operations

### Apply the principle of least privilege

Grant only the minimum permissions required for each role to perform its function.

### Setting role attributes

Important role attributes to consider:

- `LOGIN` / `NOLOGIN`: Whether the role can connect
- `CREATEDB`: Permission to create databases
- `CREATEROLE`: Permission to create other roles
- `INHERIT` / `NOINHERIT`: Whether to inherit privileges from member roles
- `CONNECTION LIMIT`: Maximum concurrent connections
