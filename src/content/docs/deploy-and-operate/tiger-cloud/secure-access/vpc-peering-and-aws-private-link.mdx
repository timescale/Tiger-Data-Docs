## Overview

This guide explains how to establish private network connectivity between your AWS infrastructure and Tiger Cloud using VPC peering or AWS PrivateLink. Private connectivity keeps your database traffic off the public internet, reducing latency and improving security.

## Prerequisites

- An active Tiger Cloud account with a deployed database service
- AWS account with appropriate IAM permissions to create VPC peering connections or PrivateLink endpoints
- Understanding of your VPC CIDR ranges to avoid IP address conflicts
- Network administrator access to configure security groups and route tables

## Understanding your connectivity options

This section compares VPC peering and AWS PrivateLink to help you choose the right approach for your use case.

### VPC peering

VPC peering creates a direct network connection between two VPCs, allowing resources in either VPC to communicate as if they were on the same network.

**Best suited for:**
- Simple, pairwise VPC connections within the same region
- Scenarios where you need bidirectional connectivity
- Environments with a small number of VPCs to connect

### AWS PrivateLink

AWS PrivateLink provides private connectivity to Tiger Cloud without exposing traffic to the public internet. Unlike VPC peering, PrivateLink creates a unidirectional connection to a specific service endpoint.

**Best suited for:**
- Connecting multiple VPCs to Tiger Cloud without managing peering relationships
- Cross-account connectivity with minimal network exposure
- Scenarios requiring fine-grained access control to specific services

## Security considerations

Best practices for securing your private connectivity:

- Implement least-privilege access in security groups
- Use network ACLs as an additional layer of defense
- Monitor VPC Flow Logs for unusual traffic patterns
- Regularly audit peering connections and endpoints

## Cost considerations

Understanding the pricing for each connectivity option:

## Troubleshooting

Common issues and their solutions:

- Peering connection stuck in pending state
- Route table misconfiguration preventing connectivity
- Security group rules blocking database traffic
- DNS resolution failures with PrivateLink endpoints
- CIDR block conflicts between peered VPCs
