## Overview

Logging in Managed Service for TimescaleDB (MST) provides visibility into database operations, query execution, errors, and security events. Properly configured logging helps with troubleshooting, performance optimization, and compliance requirements.

## Prerequisites

- An active MST service instance
- Access to the MST console with appropriate permissions
- Understanding of PostgreSQL logging concepts (recommended)

## Log types

This section describes the different types of logs available in MST.

### Query logs

Logs of SQL statements executed against the database, useful for debugging and performance analysis.

### Error logs

Records of database errors, warnings, and notices that help identify issues.

### Connection logs

Logs of connection and disconnection events, useful for security auditing and troubleshooting connectivity issues.

### Audit logs

Detailed records of database activities for compliance and security monitoring.

### Slow query logging

### Statement logging options

Configuring `log_statement` settings:
- `none` - No statement logging
- `ddl` - Log DDL statements (CREATE, ALTER, DROP)
- `mod` - Log DDL and data modification statements
- `all` - Log all statements (use with caution in production)

## Troubleshooting

Common issues and solutions related to logging.

- **Logs not appearing**: Verify logging is enabled and check retention settings
- **Excessive log volume**: Review log_statement and log_min_duration_statement settings
- **Missing query logs**: Ensure appropriate log levels are configured
- **Storage concerns**: Adjust retention policies and consider log forwarding
