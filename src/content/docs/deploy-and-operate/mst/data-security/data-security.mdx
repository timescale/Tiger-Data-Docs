## Overview

Managed Service for TimescaleDB (MST) provides comprehensive data security through encryption, compliance certifications, and security best practices. This guide covers how your data is protected at rest, in transit, and through the platform's security architecture.

## Prerequisites

- Understanding of your organization's compliance requirements
- Familiarity with encryption concepts
- Knowledge of your data classification and sensitivity levels

## Encryption

MST encrypts your data at multiple layers to protect against unauthorized access.

### Encryption at rest

All data stored in MST is encrypted at rest using industry-standard encryption.

- **Algorithm** - AES-256 encryption for all stored data
- **Key management** - Keys managed through cloud provider KMS
- **Coverage** - Includes database files, backups, and tiered storage
- **Transparent operation** - No application changes required

### Encryption in transit

All network communication is encrypted using TLS.

- **Protocol** - TLS 1.2 or higher for all connections
- **Certificate management** - Automatic certificate provisioning and renewal
- **Client verification** - Optional mutual TLS (mTLS) for enhanced security
- **Internal traffic** - Encryption between database nodes and storage

### Backup encryption

Automated backups inherit the same encryption protections.

- Backup files encrypted at rest
- Secure transfer during backup and restore operations
- Point-in-time recovery maintains encryption

## Compliance certifications

MST maintains compliance with major security and privacy frameworks.

### SOC 2

Service Organization Control 2 compliance demonstrates controls for security, availability, and confidentiality.

- Type II certification
- Annual third-party audits
- Addresses the five trust services criteria

### HIPAA

Health Insurance Portability and Accountability Act compliance for healthcare data.

- Business Associate Agreements (BAA) available
- Technical safeguards for protected health information (PHI)
- Audit logging and access controls

### GDPR

General Data Protection Regulation compliance for EU personal data.

- Data processing agreements
- Data residency options (EU regions)
- Right to erasure support
- Data portability

### Additional certifications

- ISO 27001
- PCI DSS (for applicable use cases)
- Regional certifications as required

Control where your data is physically stored.

### Region selection

Choose the cloud region for your MST instance based on:

- Regulatory requirements
- Data sovereignty laws
- Latency to your applications
- Disaster recovery needs

### Cross-region replication

If enabled, understand how data replication affects data residency.

## Access controls

Security features that control who can access your data.

### Database-level controls

- Role-based access control (RBAC)
- Row-level security (RLS)
- Column-level permissions
- Audit logging with pgAudit

### Platform-level controls

- Multi-factor authentication for console access
- API key management
- IP allowlisting
- VPC peering and private endpoints

## Security best practices

Recommendations for maintaining a strong security posture.

### Credential management

- Use secrets managers for database credentials
- Rotate credentials regularly
- Avoid embedding credentials in application code
- Use separate credentials for different applications

### Monitoring and alerting

- Enable audit logging for sensitive operations
- Monitor for failed authentication attempts
- Set up alerts for unusual query patterns
- Review access logs regularly

### Data handling

- Classify data by sensitivity level
- Apply appropriate access controls per classification
- Use parameterized queries to prevent SQL injection
- Sanitize and validate all input data

How MST handles security incidents.

### Platform security incidents

- Remediation processes

### Customer responsibilities

- Reporting suspected incidents
- Securing application-layer access
- Managing database user credentials

Common security-related issues.
