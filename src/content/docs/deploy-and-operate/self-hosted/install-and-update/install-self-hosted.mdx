## Overview

TimescaleDB is a PostgreSQL extension that enables high-performance time-series workloads. This guide covers how to install TimescaleDB on your self-hosted PostgreSQL instance using various methods including Docker, package managers, and building from source.

## Prerequisites

- PostgreSQL 13 or later installed (see version compatibility below)
- Superuser access to the PostgreSQL instance
- Root or sudo access to the server (for package installations)

### PostgreSQL version compatibility

TimescaleDB supports PostgreSQL 13 through 17. Avoid these specific PostgreSQL minor versions due to a binary interface issue: 17.1, 16.5, 15.9, 14.14, 13.17, 12.21. Use 17.2, 16.6, 15.10, or higher instead.

## Post-installation configuration

### Configure shared_preload_libraries

Add TimescaleDB to the `shared_preload_libraries` setting in postgresql.conf.

### Run timescaledb-tune

Use the timescaledb-tune utility to optimize PostgreSQL settings for TimescaleDB.

### Restart PostgreSQL

Apply configuration changes by restarting the PostgreSQL service.

### Enable the extension

Create the TimescaleDB extension in your database.

```sql
CREATE EXTENSION IF NOT EXISTS timescaledb;
```

### Verify installation

Confirm TimescaleDB is installed correctly.

## Production recommendations

For production environments, implement these additional measures:

- Incremental backups and point-in-time recovery
- High availability replication across availability zones
- Automatic failure detection with fast restarts
- Asynchronous replicas for read scaling
- Connection poolers for client connection scaling
