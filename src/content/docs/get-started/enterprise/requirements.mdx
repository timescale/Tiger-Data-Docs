TimescaleDB Enterprise runs on Linux hosts that you provide: a console host, one or more database
hosts, and an optional backup host. This page lists the supported operating systems, hardware, and
network requirements.

## Supported operating systems

Database and backup hosts:

- Debian 11, 12
- Ubuntu 20.04, 22.04, 24.04 (amd64 or arm64)
- RHEL 8.3 and later, Rocky Linux 8 and 9, AlmaLinux 8 and 9 (x86_64)

The console host can run any Linux distribution with Docker Engine 24 or later and Docker Compose v2.
Windows is not supported.

## Hardware

Two hosts is the standard layout: one console host and one database host. Add a third host for a
dedicated backup target, or collapse everything onto a single host for evaluation.

| Role | Purpose | Minimum |
|------|---------|---------|
| Console host | Runs the console stack | 2 vCPU, 8 GB RAM, 40 GB disk |
| Database host | Runs {C.TIMESCALE_DB} and stores your data | 4 vCPU, 16–32 GB RAM, disk sized for your workload |
| Backup host (optional) | Stores backups | 2 vCPU, 8 GB RAM, disk at least twice your database size |

## Network and firewall

The console reaches each host over SSH, and collects health and metrics over several other ports.
Open the following ports from the console host to the target hosts:

| Port | Target host | Purpose |
|------|-------------|---------|
| 22 | Database, backup | SSH: deployment, log collection, backups, and health checks |
| 8008 | Database | High-availability coordination |
| 9100 | Database, backup | Host metrics |
| 9187 | Database | Database metrics |
| 9399 | Database | SQL metrics |
| 9127 | Database | Connection pooler metrics |

Ports `5432` and `6432` are not required by the console. Open them only if your applications connect
directly to the database. A blocked port is the most common cause of failed health checks and empty
dashboards.
