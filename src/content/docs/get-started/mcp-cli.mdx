{C.MCP_LONG} gives your AI assistant access to {C.CLOUD_LONG} so you can manage {C.SERVICE_SHORT}s and query your data using natural language.

{C.MCP_LONG} is built into the {C.CLI_LONG} binary. It mirrors {C.CLI_SHORT} functionality and is wired to {C.COMPANY} documentation, so your AI assistant can answer questions with up-to-date guidance. This page walks you through installing {C.CLI_LONG}, configuring authentication for {C.MCP_LONG}, and managing {C.CLOUD_LONG} resources from your AI assistant.

## Prerequisites

Before you start:

- **Create a {C.ACCOUNT_LONG}** and (optionally) a target {C.PROJECT_SHORT}.
- **Install an AI assistant** on your machine with an active API key.

<Callout variant="note" title="Supported clients may change">
The following AI assistants are **automatically** configured by {C.MCP_LONG}: `claude-code`, `cursor`, `windsurf`, `codex`, `gemini/gemini-cli`, `vscode/code/vs-code`. Support for additional clients is added over time; if yours isn't listed, use [manual configuration](#manually-configure-tiger-mcp) below.
</Callout>

## Install and configure {C.MCP_LONG}

{C.MCP_LONG} is bundled with {C.CLI_LONG}.

<NumberedList>
  <NumberedItem title={`Install ${C.CLI_LONG}`}>
    In a terminal, install the {C.CLI_SHORT} using the method for your platform (see [{C.CLOUD_LONG} documentation](https://www.tigerdata.com/docs) for the latest install command).
  </NumberedItem>
  <NumberedItem title="Set up API credentials">
    1. **Log in to {C.CLOUD_LONG}**
       Run:
       ```bash
       tiger auth login
       ```
       {C.CLI_LONG} opens the browser for {C.CONSOLE_SHORT}. Log in and click **Authorize**.

       <Callout variant="warning" title="Credential limit">
       You can have a maximum of **10 active client credentials**. If login fails, open [credentials](https://console.cloud.timescale.com) and remove an unused credential.
       </Callout>

    2. **Select a {C.PROJECT_LONG}**
       If you have multiple {C.PROJECT_SHORT}s, the {C.CLI_SHORT} will prompt you to choose one (e.g. Tiger Project, company-wide project, or department project). If you have only one {C.PROJECT_SHORT}, this step is skipped.

       Credentials are stored in the system keychain (or credential manager) when possible. If that fails, they are stored in `~/.config/tiger/credentials` with restricted permissions (600). Configuration is stored by default in `~/.config/tiger/config.yaml`.

    3. **Confirm the connection**
       List {C.SERVICE_SHORT}s to verify authentication:
       ```bash
       tiger service list
       ```
       You'll see either an empty list with a prompt to create a {C.SERVICE_SHORT}, or a table of your {C.SERVICE_SHORT}s ({C.SERVICE_SHORT} ID, name, status, type, region, created).

  </NumberedItem>
  <NumberedItem title={`Install ${C.MCP_LONG}`}>

    Run:

    ```bash
    tiger mcp install
    ```

    Choose the MCP client to integrate with (for example, Claude Code, Cursor, Windsurf, Codex, Gemini CLI, VS Code) and press `Enter`.

<Callout variant="note" title={`${C.CLI_SHORT} and ${C.MCP_SHORT} commands`}>
The exact list of clients and subcommands (for example, `tiger mcp install`, `tiger mcp list`) can change with new {C.CLI_SHORT} releases. If a command fails, check the latest [{C.MCP_LONG} docs](https://www.tigerdata.com/docs/ai/latest/mcp-server) or run `tiger mcp --help`.
</Callout>
  </NumberedItem>
</NumberedList>

After this, you can use {C.MCP_LONG} from your AI assistant to manage {C.CLOUD_LONG}.

## Manage {C.CLOUD_LONG} from your AI assistant

Once connected, you can manage {C.SERVICE_SHORT}s and learn best practices through your assistant.

<NumberedList>
  <NumberedItem title="Start your AI assistant">
    (e.g. `claude`). It will start the {C.MCP_LONG} server and connect to {C.CLOUD_LONG}.
  </NumberedItem>
  <NumberedItem title={`Confirm ${C.MCP_SHORT} is active`}>
   Ask: *"Is the {C.MCP_LONG} server active?"* You should see a summary of available tools ({C.SERVICE_SHORT} management, database operations, documentation search, skills for {C.HYPERTABLE}s, etc.).
  </NumberedItem>
  <NumberedItem title={`List ${C.SERVICE_SHORT}s`}>
   Ask: *"Can you list my active {C.SERVICE_SHORT}s?"* to see your {C.CLOUD_LONG} {C.SERVICE_SHORT}s.
  </NumberedItem>
  <NumberedItem title={`Manage ${C.SERVICE_SHORT}s in plain language`}>
   For example: *"Create a new AI {C.SERVICE_SHORT} called bob with a replica."* The assistant will use {C.MCP_SHORT} tools to create the {C.SERVICE_SHORT}.
  </NumberedItem>
  <NumberedItem title="Get best practices">
   For example: *"I need to migrate a database with 25 million rows to {C.CLOUD_LONG}; what {C.SERVICE_SHORT} optimizations should I do before migration?"* The assistant can use docs and tools to give tailored advice.
  </NumberedItem>
</NumberedList>

## Manually configure {C.MCP_LONG}

If your MCP client isn't supported by `tiger mcp install`, add {C.MCP_LONG} manually. Many clients use a JSON config that starts the server with `tiger mcp start`:

```json
{
  "mcpServers": {
    "tiger": {
      "command": "tiger",
      "args": ["mcp", "start"]
    }
  }
}
```

<Callout variant="note" title="Config format may vary">
Config key names (e.g. `mcpServers`) and structure depend on your client. See your AI assistant's MCP documentation for the exact format and where to place the file.
</Callout>

## {C.MCP_LONG} tools

{C.MCP_LONG} exposes the following tools to your AI assistant. **Parameter names and required/optional fields may change with new {C.MCP_SHORT} versions**; use `tiger mcp get <tool_name>` or the latest [{C.MCP_LONG} docs](https://www.tigerdata.com/docs/ai/latest/mcp-server) for current definitions.

| Tool | Key parameters | Description |
|------|----------------|-------------|
| **service_list** | — | List {C.SERVICE_SHORT}s in the current {C.PROJECT_SHORT}. |
| **service_get** | `service_id` (required) | Detailed info for one {C.SERVICE_SHORT}. Optional: `with_password` (use only if the user explicitly asks for the password). |
| **service_create** | `name`, `addons`, `region`, `cpu_memory`, `replicas`, `wait`, `timeout_minutes`, `set_default`, `with_password` | Create a new {C.SERVICE_SHORT}. **WARNING:** creates billable resources. Addons: `time-series` ({C.TIMESCALE_DB}), `ai` (AI/vector). |
| **service_fork** | `service_id`, `fork_strategy` (NOW \| LAST_SNAPSHOT \| PITR), `target_time` (for PITR), `name`, `cpu_memory`, `wait`, `timeout_minutes`, `set_default`, `with_password` | Fork a {C.SERVICE_SHORT}. **WARNING:** creates billable resources. |
| **service_update_password** | `service_id`, `password` | Update `tsdbadmin` password; may disconnect existing sessions. |
| **service_start** | `service_id`, `wait`, `timeout_minutes` | Start a stopped {C.SERVICE_SHORT}. |
| **service_stop** | `service_id`, `wait`, `timeout_minutes` | Stop a running {C.SERVICE_SHORT}. |
| **service_resize** | `service_id`, `cpu_memory`, `wait`, `timeout_minutes` | Change CPU/memory. **WARNING:** affects billing; {C.SERVICE_SHORT} may be briefly unavailable. |
| **service_logs** | `service_id`, `tail`, `until`, `node` | Fetch {C.SERVICE_SHORT} logs (e.g. tail length, time range, node). |
| **db_execute_query** | `service_id`, `query`, `parameters`, `timeout_seconds`, `role`, `pooled` | Run a single SQL statement. **WARNING:** can run destructive SQL (INSERT/UPDATE/DELETE/DDL). Multi-statement not supported. |

## {C.CLI_LONG} commands for {C.MCP_SHORT}

Use these under the `tiger mcp` namespace. **Subcommands and flags may be updated in new {C.CLI_SHORT} releases.**

| Command | Description |
|--------|-------------|
| `tiger mcp install [client]` | Configure {C.MCP_LONG} for a client (e.g. `claude-code`, `cursor`, `windsurf`, `codex`, `gemini/gemini-cli`, `vscode/code/vs-code`). Flags: `--no-backup`, `--config-path`. |
| `tiger mcp list` | List {C.MCP_SHORT} tools, prompts, and resources. Optional: `--output` / `-o` (json, yaml, table). |
| `tiger mcp get <name>` | Details for one capability (e.g. `tiger mcp get service_create` or `tiger mcp get setup-timescaledb-hypertables`). Aliases: `describe`, `show`. |
| `tiger mcp start` | Start {C.MCP_LONG} (same as `tiger mcp start stdio`). |
| `tiger mcp start stdio` | Start {C.MCP_SHORT} with stdio transport. |
| `tiger mcp start http` | Start {C.MCP_SHORT} with HTTP (e.g. if your assistant doesn't support stdio). Flags: `--port` (default 8080), `--host` (default localhost). |

## Global flags

When running {C.CLI_LONG} (including {C.MCP_SHORT} commands), you can use:

| Flag | Default | Description |
|------|--------|-------------|
| `--analytics` | true | Enable/disable usage analytics. |
| `--color` | true | Enable/disable colored output. |
| `--config-dir` | `~/.config/tiger` | Config directory for `config.yaml`. |
| `--debug` | false | Enable debug logging. |
| `--help` / `-h` | — | Help for the current command. |
| `--password-storage` | keyring | Password storage: `keyring`, `pgpass`, or `none`. |
| `--service-id` | — | Default {C.SERVICE_SHORT} for subsequent commands. |
| `--skip-update-check` | false | Skip {C.CLI_SHORT} update check. |

</Callout>
