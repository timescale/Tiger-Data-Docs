<TabItem label="From source">

{C.TIMESCALE_DB} is a [{C.PG} extension](https://www.postgresql.org/docs/current/external-extensions.html) for time series and demanding workloads that ingest and query high volumes of data. You can install {C.TIMESCALE_DB} on any local system from source.

### Prerequisites

- **{C.PG}**: Install a [supported version of {C.PG}](https://www.postgresql.org/download/). We recommend not using {C.TIMESCALE_DB} with {C.PG} 17.1, 16.5, 15.9, 14.14, 13.17, or 12.21. These minor versions [introduced a breaking binary interface change](https://www.postgresql.org/about/news/postgresql-172-166-1510-1415-1318-and-1222-released-2965/) that was reverted in subsequent releases. Build with {C.PG} 17.2, 16.6, or higher.

- **Build tools**:
  - [CMake 3.11 or later](https://cmake.org/download/)
  - C language compiler (`gcc` or `clang`). On Windows, Visual Studio 2015 or later works instead — ensure you install the CMake and Git components.

<TabItem label="Cloud image (AWS)">

You can install {C.TIMESCALE_DB} on AWS from a pre-built Amazon Machine Image (AMI).

<SelfHostedCta />

The currently available pre-built cloud image is Ubuntu 20.04 Amazon EBS-backed AMI. The {C.TIMESCALE_DB} AMI uses Elastic Block Store (EBS) attached volumes, which allows you to store image snapshots, dynamic IOPS configuration, and provides data protection if the EC2 instance goes down. Choose an [EBS-optimized EC2 instance type](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ebs-optimized.html) for best performance.

<Callout variant="note">

You can also use the AMI with tools like Cloudformation, Terraform, the AWS CLI, or any AWS deployment tool that supports public AMIs.

</Callout>

1. Sign in to your [EC2 dashboard](https://console.aws.amazon.com/ec2/).
1. Navigate to `Images → AMIs`.
1. In the search bar, change the filter to `Public images` and search for `Timescale`.
1. Select the image you want to use and click `Launch instance from image`.

After installation, [connect to your instance](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/AccessingInstances.html) and run the `timescaledb-tune` script (included with `timescaledb-tools`) to configure your database.

<Callout variant="note">

After running `timescaledb-tune`, restart the {C.PG} service for changes to take effect:

```bash
sudo systemctl restart postgresql.service
```

</Callout>
