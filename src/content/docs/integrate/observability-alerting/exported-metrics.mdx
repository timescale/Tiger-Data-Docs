This page provides a list of metrics you can export with all {C.CLOUD_LONG} exporters. You can filter them by `project_id`, `service_id`, `role`, and `region`.

You can also query these metrics ad hoc, without setting up an exporter, using the [`tiger service metrics`](/reference/tiger-cloud/tiger-cli#tiger-service-metrics-available) commands in {C.CLI_LONG} or the [metrics tools](/reference/tiger-cloud/tiger-mcp#metrics-tools) in {C.MCP_LONG}.

<Callout variant="note">

The following limitations apply for replica metrics:
- For HA replicas, metrics are only exported for the primary and one HA replica.
- For read replica sets, metrics are exported for the primary/`standby_leader` and one read replica.

</Callout>

## {C.PG} metrics

These additional metrics are collected if you enable **{C.PG} metrics** when creating {C.CLOUD_LONG} exporters.
All metrics have a scrape interval of 15 seconds.

<Callout variant="note">

Prometheus exporters append `_total` to counter names. For example, `pg_stat_database_xact_commit` is exposed as `pg_stat_database_xact_commit_total`. Other exporters use the names as listed.

</Callout>

### Exporter metrics

These metrics show the health and status of the metrics collection process, including scrape duration, errors, and total scrape count.

|Metric|Description|
|-|-|
|`pg_exporter_last_scrape_duration_seconds`|Duration of the last scrape of metrics from {C.PG}.|
|`pg_exporter_last_scrape_error`|Whether the last scrape of metrics from {C.PG} resulted in an error (1 for error, 0 for success).|
|`pg_exporter_scrapes_total`|Total number of times {C.PG} was scraped for metrics.|
|`pg_exporter_user_queries_load_error`|Whether the user queries file was loaded and parsed successfully (1 for error, 0 for success).|
