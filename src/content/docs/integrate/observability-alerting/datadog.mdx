[Datadog](https://www.datadoghq.com) is a cloud-based monitoring and analytics platform that provides comprehensive visibility into applications, infrastructure, and systems through real-time monitoring, logging, and analytics.

This page explains how to:

- **Monitor {C.CLOUD_LONG} service metrics with Datadog** — Export telemetry using a {C.CLOUD_LONG} data exporter. This integration is available for [Scale and Enterprise](/deploy/tiger-cloud/understand/pricing-and-account-management#features-included-in-each-plan) pricing plans.
- **Configure Datadog Agent to collect metrics for your {C.CLOUD_LONG} service** — Use the Postgres integration in Datadog Agent. This integration is available for all pricing plans.

## Prerequisites

To follow the steps on this page:

- Create a target [{C.SERVICE_LONG}](/deploy/tiger-cloud/get-started/create-services) with the Real-time analytics capability. You need your [connection details](/integrate/find-connection-details).
- Sign up for [Datadog](https://www.datadoghq.com). You need your [Datadog API key](https://docs.datadoghq.com/account_management/api-app-keys/#add-an-api-key-or-client-token) to follow this procedure.
- Install [Datadog Agent](https://docs.datadoghq.com/getting_started/agent/#installation).

<Callout variant="note">
  This feature is currently not supported for {C.CLOUD_LONG} on Microsoft Azure.
</Callout>

## Monitor Tiger Cloud service metrics with Datadog

Export telemetry data from your {C.CLOUD_LONG} services with the time-series and analytics capability enabled to Datadog using a {C.CLOUD_LONG} data exporter. The available metrics include CPU usage, RAM usage, and storage.

### Create a data exporter

A {C.CLOUD_LONG} data exporter sends telemetry data from a {C.CLOUD_LONG} service to a third-party monitoring tool. You create an exporter on the [{C.CLOUD_LONG} project level](/deploy/tiger-cloud/secure-access/configure-role-based-access), in the same AWS region as your service:

<NumberedList>

<NumberedItem title={`In ${C.CONSOLE}, open Exporters`}>
Open the [Exporters](https://console.cloud.timescale.com/dashboard/integrations) page, under the integrations section of your Tiger Data console dashboard.
</NumberedItem>

<NumberedItem title="Click New exporter">
</NumberedItem>

<NumberedItem title="Select Metrics for Data type and Datadog for provider">

![Add Datadog exporter](https://assets.timescale.com/docs/images/tiger-cloud-console/tiger-cloud-integrations-datadog.png)

</NumberedItem>

<NumberedItem title="Choose your AWS region and provide the API key">
The AWS region must be the same for your {C.CLOUD_LONG} exporter and the Datadog provider.
</NumberedItem>

<NumberedItem title="Set Site to your Datadog region, then click Create exporter">
</NumberedItem>

</NumberedList>

### Attach a data exporter to a Tiger Cloud service

To send telemetry data to an external monitoring tool, you attach a data exporter to your {C.CLOUD_LONG} service. You can attach only one exporter to a service.

To attach an exporter:

<NumberedList>

<NumberedItem title={`In ${C.CONSOLE}, choose the service`}>
</NumberedItem>

<NumberedItem title="Click Operations > Exporters">
</NumberedItem>

<NumberedItem title="Select the exporter from the list, then click Attach exporter">
</NumberedItem>

<NumberedItem title="Restart the service if attaching a first Logs exporter">
If you are attaching a first `Logs` data type exporter, the service will need to be restarted.
</NumberedItem>

</NumberedList>

### Monitor Tiger Cloud service metrics

You can now monitor your service metrics. Use the following metrics to check the service is running correctly:

- `timescale.cloud.system.cpu.usage.millicores`
- `timescale.cloud.system.cpu.total.millicores`
- `timescale.cloud.system.memory.usage.bytes`
- `timescale.cloud.system.memory.total.bytes`
- `timescale.cloud.system.disk.usage.bytes`
- `timescale.cloud.system.disk.total.bytes`

Additionally, use the following tags to filter your results:

| Tag          | Example variable           | Description               |
| ------------ | -------------------------- | ------------------------- |
| `host`       | `us-east-1.timescale.cloud` | Host identifier           |
| `project-id` | —                          | Project identifier        |
| `service-id` | —                          | Service identifier        |
| `region`     | `us-east-1`                | AWS region                |
| `role`       | `replica` or `primary`    | For services with replicas |
| `node-id`    | —                          | For multi-node services   |

### Delete a data exporter

To remove a data exporter that you no longer need:

<NumberedList>

<NumberedItem title={`Disconnect the data exporter from your ${C.CLOUD_LONG} services`}>

<ol type="a">
  <li>In {C.CONSOLE}, choose the service.</li>
  <li>Click `Operations` &gt; `Exporters`.</li>
  <li>Click the trash can icon.</li>
  <li>Repeat for every service attached to the exporter you want to remove.</li>
</ol>

The data exporter is now unattached from all services. However, it still exists in your project.

</NumberedItem>

<NumberedItem title="Delete the exporter on the project level">

<ol type="a">
  <li>In {C.CONSOLE}, open [Exporters](https://console.cloud.timescale.com/dashboard/integrations).</li>
  <li>Next to the exporter you want to remove, click menu &gt; `Delete`.</li>
  <li>Confirm that you want to delete the data exporter.</li>
</ol>

</NumberedItem>

</NumberedList>

## Configure Datadog Agent to collect metrics for your Tiger Cloud services

Datadog Agent includes a [{C.PG} integration](https://docs.datadoghq.com/integrations/postgres/) that you use to collect detailed {C.PG} database metrics about your {C.CLOUD_LONG} services.

<NumberedList>

<NumberedItem title="Connect to your Tiger Cloud service">
For {C.CLOUD_LONG}, open an [SQL editor](/deploy/tiger-cloud/get-started/run-queries-from-console) in [Tiger Console](https://console.cloud.timescale.com/dashboard/services). For self-hosted TimescaleDB, use [psql](/integrate/query-administration/psql).
</NumberedItem>

<NumberedItem title="Add the datadog user to your Tiger Cloud service">

Run the following SQL (replace `&lt;password&gt;` with a secure password):

```sql
CREATE USER datadog WITH PASSWORD '<password>';
GRANT pg_monitor TO datadog;
GRANT SELECT ON pg_stat_database TO datadog;
```

</NumberedItem>

<NumberedItem title="Test the connection and rights for the datadog user">

Update the following command with your [connection details](/integrate/find-connection-details), then run it from the command line. You should see output from the `pg_stat_database` table, which means you have given the correct rights to `datadog`.

```bash
psql "postgres://datadog:<datadog password>@<host>:<port>/tsdb?sslmode=require" -c "SELECT * FROM pg_stat_database LIMIT(1);" && echo -e "\e[0;32mPostgres connection - OK\e[0m" || echo -e "\e[0;31mCannot connect to Postgres\e[0m"
```

</NumberedItem>

<NumberedItem title="Connect Datadog to your Tiger Cloud service">

Configure the [Datadog Agent {C.PG} configuration file](https://docs.datadoghq.com/database_monitoring/setup_postgres/selfhosted?tab=postgres15). It is usually located on the Datadog Agent host at: **Linux** `/etc/datadog-agent/conf.d/postgres.d/conf.yaml`, **MacOS** `/opt/datadog-agent/etc/conf.d/postgres.d/conf.yaml`, **Windows** `C:\ProgramData\Datadog\conf.d\postgres.d\conf.yaml`. Use your [connection details](/integrate/find-connection-details) to update the following and add it to the configuration file:

```yaml
init_config:

instances:
  - host: <host>
    port: <port>
    username: datadog
    password: "<datadog's password>"
    dbname: tsdb
    disable_generic_tags: true
```

</NumberedItem>

<NumberedItem title="Add Tiger Cloud metrics tags">

Tags make it easier to build Datadog dashboards that combine metrics from the {C.CLOUD_LONG} data exporter and Datadog Agent. Use your [connection details](/integrate/find-connection-details) to update the following and add it to `&lt;datadog_home&gt;/datadog.yaml`:

```yaml
tags:
  - project-id:<project-id>
  - service-id:<service-id>
  - region:<region>
```

</NumberedItem>

<NumberedItem title="Restart Datadog Agent">
See how to [Start, stop, and restart Datadog Agent](https://docs.datadoghq.com/agent/configuration/agent-commands/#start-stop-and-restart-the-agent).
</NumberedItem>

</NumberedList>

Metrics for your {C.CLOUD_LONG} service are now visible in Datadog. Check the Datadog {C.PG} integration documentation for a comprehensive list of [metrics](https://docs.datadoghq.com/integrations/postgres/?tab=host#metrics) collected.
