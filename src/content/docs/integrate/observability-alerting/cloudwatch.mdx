[Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) is a monitoring and observability service designed to help collect, analyze, and act on data from applications, infrastructure, and services running in AWS and on-premises environments.

You can export telemetry data from your {C.CLOUD_LONG} services with the time-series and analytics capability enabled to CloudWatch. The available metrics include CPU usage, RAM usage, and storage. This integration is available for [Scale and Enterprise](/deploy/tiger-cloud/understand/pricing-and-account-management#features-included-in-each-plan) pricing tiers.

This page explains how to export telemetry data from your {C.CLOUD_LONG} service into CloudWatch by creating a {C.CLOUD_LONG} data exporter, then attaching it to the service.

## Prerequisites

To follow the steps on this page:

- Create a target [{C.SERVICE_LONG}](/deploy/tiger-cloud/get-started/create-services) with Real-time analytics enabled. You need your [connection details](/integrate/find-connection-details).
- Sign up for [Amazon CloudWatch](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/GettingSetup.html).

<Callout variant="note">
This feature is currently not supported for {C.CLOUD_LONG} on Microsoft Azure.
</Callout>

## Create a data exporter

A {C.CLOUD_LONG} data exporter sends telemetry data from a {C.CLOUD_LONG} service to a third-party monitoring tool. You create an exporter on the [{C.CLOUD_LONG} project level](/deploy/tiger-cloud/secure-access/configure-role-based-access), in the same AWS region as your service:

<NumberedList>

<NumberedItem title={`In ${C.CONSOLE}, open Exporters`}>
Open the [Exporters](https://console.cloud.timescale.com/dashboard/integrations) page, under the integrations section of your Tiger Data console dashboard.
</NumberedItem>

<NumberedItem title="Click New exporter">
</NumberedItem>

<NumberedItem title="Select the data type and specify AWS CloudWatch for provider">

![Add CloudWatch data exporter](https://assets.timescale.com/docs/images/tiger-cloud-console/tiger-cloud-integrations-cloudwatch.png)

</NumberedItem>

<NumberedItem title="Provide your AWS CloudWatch configuration">

When doing so, your AWS region must be the same for your {C.CLOUD_LONG} exporter and AWS CloudWatch Log group.

The exporter name appears in {C.CONSOLE}; best practice is to make this name easily understandable.

For CloudWatch credentials, either use an [existing CloudWatch Log group](https://console.aws.amazon.com/cloudwatch/home#logsV2:log-groups) or [create a new one](https://console.aws.amazon.com/cloudwatch/home#logsV2:log-groups/create-log-group). If you're uncertain, use the default values. 

For more information, see [Working with log groups and log streams](https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/Working-with-log-groups-and-streams.html) within the Amazon CloudWatch documentation.

</NumberedItem>

<NumberedItem title="Choose the authentication method to use for the exporter">

![Add CloudWatch authentication](https://assets.timescale.com/docs/images/tiger-cloud-console/tiger-cloud-integrations-cloudwatch-authentication.png)

<ol type="a">
  <li>In AWS, navigate to [IAM &gt; Identity providers](https://console.aws.amazon.com/iam/home#/identity_providers), then click `Add provider`.</li>
  <li>Update the new identity provider with your details: set `Provider URL` to the [region where you are creating your exporter](#reference).</li>
</ol>

![OIDC provider creation](https://assets.timescale.com/docs/images/aws-create-iam-oicd-provider.png)

<ol type="a" start="3">
  <li>Click `Add provider`.</li>
  <li>In AWS, navigate to [IAM &gt; Roles](https://console.aws.amazon.com/iam/home#/roles), then click `Create role`.</li>
  <li>Add your identity provider as a Web identity role and click `Next`.</li>
</ol>

![Web identity role creation](https://assets.timescale.com/docs/images/aws-create-role-web-identity.png)

<ol type="a" start="6">
  <li>Set the following permission and trust policies as required by CloudWatch (see [AWS documentation](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/GettingSetup.html) for policy examples).</li>
  <li>Click `Add role`.</li>
</ol>

</NumberedItem>

<NumberedItem title="Select the AWS region and create the exporter">
Select the AWS region your CloudWatch services run in, then click `Create exporter`.
</NumberedItem>

</NumberedList>

## Attach a data exporter to a Tiger Cloud service

To send telemetry data to an external monitoring tool, you attach a data exporter to your {C.CLOUD_LONG} service. You can attach only one exporter to a service.

To attach an exporter:

<NumberedList>

<NumberedItem title={`In ${C.CONSOLE}, choose the service`}>
</NumberedItem>

<NumberedItem title="Click Operations > Exporters">
</NumberedItem>

<NumberedItem title="Select the exporter from the list, then click Attach exporter">
</NumberedItem>

<NumberedItem title="Restart the service if attaching a first Logs exporter">
If you are attaching a first `Logs` data type exporter, the service will need to be restarted.
</NumberedItem>

</NumberedList>

## Monitor Tiger Cloud service metrics

You can now monitor your service metrics. Use the following metrics to check the service is running correctly:

- `timescale.cloud.system.cpu.usage.millicores`
- `timescale.cloud.system.cpu.total.millicores`
- `timescale.cloud.system.memory.usage.bytes`
- `timescale.cloud.system.memory.total.bytes`
- `timescale.cloud.system.disk.usage.bytes`
- `timescale.cloud.system.disk.total.bytes`

Additionally, use the following tags to filter your results:

| Tag          | Example variable          | Description               |
| ------------ | ------------------------- | ------------------------- |
| `host`       | `us-east-1.timescale.cloud` | Host identifier           |
| `project-id` | —                         | Project identifier        |
| `service-id` | —                         | Service identifier        |
| `region`     | `us-east-1`               | AWS region                |
| `role`       | `replica` or `primary`    | For services with replicas |
| `node-id`    | —                         | For multi-node services   |

## Delete a data exporter

To remove a data exporter that you no longer need:

<NumberedList>

<NumberedItem title={`Disconnect the data exporter from your ${C.CLOUD_LONG} services`}>

<ol type="a">
  <li>In {C.CONSOLE}, choose the service.</li>
  <li>Click `Operations` &gt; `Exporters`.</li>
  <li>Click the trash can icon.</li>
  <li>Repeat for every service attached to the exporter you want to remove.</li>
</ol>

The data exporter is now unattached from all services. However, it still exists in your project.

</NumberedItem>

<NumberedItem title="Delete the exporter on the project level">

<ol type="a">
  <li>In {C.CONSOLE}, open [Exporters](https://console.cloud.timescale.com/dashboard/integrations).</li>
  <li>Next to the exporter you want to remove, click menu &gt; `Delete`.</li>
  <li>Confirm that you want to delete the data exporter.</li>
</ol>

</NumberedItem>

</NumberedList>
