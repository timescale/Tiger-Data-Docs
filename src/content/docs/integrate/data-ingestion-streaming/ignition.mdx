[Ignition][ignition] is a SCADA system used to connect data, design industrical systems, and monitor automated processes in real time.

This page shows you how to connect Ignition to your {C.SERVICE_LONG} to stream industrial data into {C.TIMESCALE_DB}.

## Prerequisites

<IntegrationPrereqs />

- An [Ignition][ignition-download] instance with admin access

## Create a {C.SERVICE_LONG} connection in Ignition

1. Navigate your browser to the ignition gateway screen and sign in with an admin account. Open **Connections** / **Database Connections** and select **Create Database Connection +**.

1. Select **PostgreSQL** as the driver (included in every standard ignition install).

1. Give the database connection a name. Add the **username**, **password**, and **connection url** that was downloaded during Tiger Data service setup . Select **Create Database Connection**.

1. Verify that the database connection was created and status is valid. If any errors appear, consult the [Ignition manual][ignition-manual].

## Setup {C.SERVICE_LONG} as a historian

1. On the Ignition Gateway, select **Services** / **Historians** and **Create Historian +**.

1. Select **SQL Historian**.

1. Add a name for the historian, and select the {C.SERVICE_LONG} database connected in section 1 as the Data Source. Disable Partitioning.

<Callout variant="warning">
If you don’t disable partitioning during the initial setup, and actively use the historian beyond the partition length, ignition will create multiple history tables. This will make setting up Tiger Data optimizations more difficult and reduce the convenience of having all historical data in one table.
</Callout>

1. Verify the new historian is enabled and running.

1. Before proceeding to the next section, make sure there is data flowing into the historian. This can be done by creating any tag and setting **History Enabled** to **True** That will guarantee that the historian table is created.

## Optimize {C.TIMESCALE_DB} for ignition workloads

Ignition will automatically create the table in {C.SERVICE_LONG}, but will not set it up as a {C.HYPERTABLE}. The following instructions can be performed within Ignition's [SQL Editor][ignition-sql-editor], the [CLOUD_LONG Console][tiger console], or any other SQL editor.

1. Convert the auto-created historian table to a hypertable.

   ```sql
   SELECT create_hypertable(
      'sqlth_1_data','t_stamp',
      migrate_data => 'true', 
      chunk_time_interval => 86400000
   );
   ```
   <Callout variant="note">
   Chunk size must be defined in milliseconds. Recommended chunk size should aim for about 1-20 million records per chunk. That's about 1 day (86,400,000ms) for 10,000 tags/min or 1 hour (3,600,000ms) for 300,000 tags/min.
   </Callout>

1. Optional: Add compression, and set the compression policy

   ```sql
   ALTER TABLE sqlth_1_data SET (
   timescaledb.compress,
   timescaledb.compress_segmentby = 'tagid',
   timescaledb.compress_orderby = 't_stamp DESC'
   );
   SELECT add_compression_policy('sqlth_1_data', INTERVAL '7 days');
   ```

1. Optional: Add retention policy
   ```sql
      SELECT add_retention_policy('tag_table', INTERVAL '1 year');
   ```

You have successfully integrated Ignition with {C.CLOUD_LONG}.
