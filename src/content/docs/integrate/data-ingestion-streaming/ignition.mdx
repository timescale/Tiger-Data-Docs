[Ignition](https://inductiveautomation.com/) is a SCADA system used to connect data, design industrial systems, and monitor automated processes in real time.

This page shows you how to connect Ignition to your {C.SERVICE_LONG} to stream industrial data into {C.CLOUD_LONG}.

<Prerequisites context="integration">
<IntegrationPrereqs />
<ConnectionDetails />

- An [Ignition](https://inductiveautomation.com/downloads/) instance with admin access
</Prerequisites>

## Create a {C.CLOUD_LONG} service connection in Ignition

<NumberedList>
  <NumberedItem title="Sign in to the Ignition Gateway">
    Navigate your browser to the Ignition Gateway screen and sign in with an admin account. Open `Connections` > `Database Connections` and select `Create Database Connection +`.
  </NumberedItem>
  <NumberedItem title={`Select the ${C.PG} driver`}>
    Select `PostgreSQL` as the driver (included in every standard Ignition install).
  </NumberedItem>
  <NumberedItem title="Configure the database connection">
    1. Give the database connection a name.
    1. Add the `username`, `password`, and `connection url` using your [{C.SERVICE_LONG} connection details](/integrate/find-connection-details).
    1. Select `Create Database Connection`.
  </NumberedItem>
  <NumberedItem title="Verify the connection">
    Verify that the database connection was created and status is valid. If any errors appear, consult the [Ignition manual](https://www.docs.inductiveautomation.com/).
  </NumberedItem>
</NumberedList>

## Set up your {C.CLOUD_LONG} service as a historian

<NumberedList>
  <NumberedItem title="Create a historian">
    On the Ignition Gateway, select `Services` > `Historians` and `Create Historian +`.
  </NumberedItem>
  <NumberedItem title="Select SQL Historian">
    Select `SQL Historian`.
  </NumberedItem>
  <NumberedItem title="Name the historian and disable partitioning">
    Add a name for the historian, and select the {C.SERVICE_LONG} database connected in section 1 as the Data Source. Disable Partitioning.

    <Callout variant="warning">
    If you don’t disable partitioning during the initial setup, and actively use the historian beyond the partition length, Ignition will create multiple history tables. This will make setting up {C.CLOUD_LONG} optimizations more difficult and reduce the convenience of having all historical data in one table.
    </Callout>
  </NumberedItem>
  <NumberedItem title="Verify the historian is running">
    Verify the new historian is enabled and running.
  </NumberedItem>
  <NumberedItem title="Start data flowing into the historian">
    Before proceeding to the next section, make sure there is data flowing into the historian. This can be done by creating any tag and setting `History Enabled` to `True`. That will guarantee that the historian table is created.
  </NumberedItem>
</NumberedList>

Ignition will automatically create the table in {C.SERVICE_LONG}, but will not set it up as a {C.HYPERTABLE}. The following instructions can be performed within Ignition's [SQL Editor](https://www.docs.inductiveautomation.com/docs/7.9/sql-in-ignition/common-sql-tasks/simple-database-editor), the [{C.CONSOLE_LONG}](/build/data-management/run-queries-from-tiger-console), or any other SQL editor.

## Optimize for Ignition workloads

<NumberedList>
  <NumberedItem title={`Convert the auto-created historian table to a ${C.HYPERTABLE}`}>
    ```sql
    SELECT create_hypertable(
       'sqlth_1_data','t_stamp',
       migrate_data => 'true',
       chunk_time_interval => 86400000
    );
    ```

    <Callout variant="note">
    Chunk size must be defined in milliseconds. Recommended chunk size should aim for about 1-20 million records per chunk. That's about 1 day (86,400,000ms) for 10,000 tags/min or 1 hour (3,600,000ms) for 300,000 tags/min.
    </Callout>
  </NumberedItem>
  <NumberedItem title={`Optional: enable the ${C.COLUMNSTORE} and add a policy`}>
    ```sql
    ALTER TABLE sqlth_1_data SET (
    timescaledb.enable_columnstore = true,
    timescaledb.segmentby = 'tagid',
    timescaledb.orderby = 't_stamp DESC'
    );
    SELECT add_columnstore_policy('sqlth_1_data', after => INTERVAL '7 days');
    ```
  </NumberedItem>
  <NumberedItem title="Optional: add retention policy">
    ```sql
    SELECT add_retention_policy('tag_table', INTERVAL '1 year');
    ```
  </NumberedItem>
</NumberedList>

You have successfully integrated Ignition with {C.CLOUD_LONG}.
