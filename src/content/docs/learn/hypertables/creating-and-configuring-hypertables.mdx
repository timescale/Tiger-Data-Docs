Hypertables turn ordinary {C.PG} tables into time-partitioned tables made of **chunks**, so you can scale to very large datasets. Start with a normal table, then call `create_hypertable()`.

## Create a hypertable

1. Create a regular {C.PG} table with your time (or integer) partitioning column.
2. Call `create_hypertable()` to register it as a hypertable.

Key arguments to understand:

- **`chunk_time_interval`**: Default is often seven days. Size chunks for your ingest rate and memory. Larger chunks mean fewer chunks; smaller chunks mean more chunks and more planning overhead. See [Sizing hypertable chunks](/learn/hypertables/sizing-hypertable-chunks).
- **`create_default_indexes`**: An index on the partitioning column is created by default. For large bulk loads into a **new** hypertable, you can set this to `false` and add indexes later. If you use a unique or primary key, the partitioning column must appear in that constraint.
- **`migrate_data`**: To convert a table that **already has rows**, set `migrate_data` appropriately so existing data is migrated into chunks. For very large tables, creating an empty hypertable and loading data in batches is often safer and more predictable.
