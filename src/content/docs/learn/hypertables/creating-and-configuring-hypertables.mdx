{C.HYPERTABLE_CAP}s turn ordinary {C.PG} tables into time-partitioned tables made of
**{C.CHUNK}s**, so you can scale to very large datasets. Add
`WITH (timescaledb.hypertable)` to a standard `CREATE TABLE` statement to create one.

## Create a {C.HYPERTABLE}

Create a {C.HYPERTABLE} from scratch in {C.CONSOLE_LONG} or with SQL.

<TabItem label="SQL">

The simplest form auto-detects the partition column from the first `timestamptz` column
and adds `NOT NULL` automatically if needed:

```sql
CREATE TABLE sensor_data (
  time        TIMESTAMPTZ NOT NULL,
  device_id   INT,
  temperature DOUBLE PRECISION
) WITH (timescaledb.hypertable);
```

If your table has multiple timestamp columns or uses a non-standard name, specify the
partition column explicitly:

```sql
CREATE TABLE order_events (
  created_at  TIMESTAMPTZ NOT NULL,
  order_id    BIGINT,
  status      TEXT
) WITH (
  timescaledb.hypertable,
  timescaledb.partition_column = 'created_at'
);
```

</TabItem>

## Configuration options

Set these options in the `WITH` clause to control how the {C.HYPERTABLE} is created:

| Option | Default | Description |
|---|---|---|
| `timescaledb.hypertable` | — | Required. Marks the table as a {C.HYPERTABLE}. |
| `timescaledb.partition_column` | Auto-detected | The column used to partition data into {C.CHUNK}s. Auto-detected from the first `timestamptz` column. Required if the table has no `timestamptz` column or has more than one. |
| `timescaledb.chunk_interval` | `7 days` | The time range each {C.CHUNK} covers. Tune this for your ingest rate and memory. See [Sizing {C.HYPERTABLE} {C.CHUNK}s](/learn/hypertables/sizing-hypertable-chunks). |
| `timescaledb.create_default_indexes` | `true` | Creates an index on the partition column automatically. Set to `false` for large bulk loads where you want to add indexes after loading. |

### Set {C.CHUNK} interval

Choose a {C.CHUNK} interval so that all active {C.CHUNK}s fit in memory. The default is
7 days, which works well for many workloads. For high-throughput ingestion, a shorter interval
like 1 day may be better:

```sql
CREATE TABLE high_throughput_metrics (
  time        TIMESTAMPTZ NOT NULL,
  device_id   INT,
  value       DOUBLE PRECISION
) WITH (
  timescaledb.hypertable,
  timescaledb.chunk_interval = '1 day'
);
```

### Disable default indexes

For large bulk loads into a new {C.HYPERTABLE}, skip automatic index creation and add indexes
after the data is loaded:

```sql
CREATE TABLE bulk_load_target (
  time        TIMESTAMPTZ NOT NULL,
  device_id   INT,
  value       DOUBLE PRECISION
) WITH (
  timescaledb.hypertable,
  timescaledb.create_default_indexes = false
);

-- Load data first, then create indexes
CREATE INDEX ON bulk_load_target (time DESC);
CREATE INDEX ON bulk_load_target (device_id, time DESC);
```

## Convert an existing table

Convert an existing {C.PG} table that already has data to a {C.HYPERTABLE} in
{C.CONSOLE_LONG} or with SQL.

<TabItem label={C.CONSOLE}>

To convert an existing table in {C.CONSOLE_LONG}:

<NumberedList>

  <NumberedItem title={`Select your ${C.SERVICE_SHORT}, then click \`Actions\``}>
  </NumberedItem>

  <NumberedItem title={`Under \`Goals\`, find \`Create a hypertable\` and click \`Get started\``}>

    In the wizard, select the `Convert existing table` tab.

    <Image src={imgConvertStart} alt="Create a hypertable wizard in Tiger Console" />

  <NumberedItem title="Choose the table to convert">

  <NumberedItem title="Configure the partition column">

    Under `Configure`, select the column used to partition data into {C.CHUNK}s, for

  </NumberedItem>

  <NumberedItem title="Transform the table into a hypertable">

    Your table is converted to a {C.HYPERTABLE}.

    <Image src={imgConvertComplete} alt="A table converted to a hypertable in Tiger Console" />

  </NumberedItem>

</NumberedList>

</TabItem>

<TabItem label="SQL">

To convert a {C.PG} table that already has data, use the `create_hypertable()` function
with `migrate_data`:

```sql
SELECT create_hypertable('existing_table', by_range('time'), migrate_data => true);
```

For very large tables, this can be slow and lock-heavy. A safer approach is to create
an empty {C.HYPERTABLE} and load data in batches:

```sql
CREATE TABLE new_table (LIKE existing_table INCLUDING ALL)
  WITH (timescaledb.hypertable);

INSERT INTO new_table SELECT * FROM existing_table;
```
