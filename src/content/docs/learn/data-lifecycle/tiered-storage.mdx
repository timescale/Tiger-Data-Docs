---
title: "Tiered storage on Tiger Cloud"
description: "Layers from hot EBS to object storage, tiering policies, manual tier and untier, and querying tiered data on Tiger Cloud."
---

Tiger Cloud uses **layered storage**: hot data on high-performance volumes, **compressed** data as another layer, and optionally **object storage** for colder, less frequently accessed data, see [About data tiering](/learn/data-management/storage/about-storage-tiers). Object storage can reduce cost, extend beyond typical volume limits, and remains queryable when enabled.

## Enable tiering and add a policy

1. [Enable tiered storage](/build/data-management/storage/manage-storage#enable-tiered-storage) from the service console.
2. Add a [tiering policy](/build/data-management/storage/manage-storage#add-a-tiering-policy) with `add_tiering_policy()` (example SQL in the Timescale docs).

## Remove a policy

Call `remove_tiering_policy()` to drop an existing policy.

## Manual tier and untier

You may [tier or untier chunks manually](/learn/data-lifecycle/tiered-storage), for example when approaching storage limits. **Tiered data is immutable**; to modify it, **untier** first (`untier_chunk()`).

### Explore tiered chunks

After `tier_chunk()`, inspect which chunks are scheduled or tiered using the catalog views documented in the tiering guides (wording varies by version, follow the current Timescale tiering docs).

## Disable tiering

To move back entirely to high-performance storage, ensure you have space, then **untier** or **drop** tiered data before disabling tiering in the console.

## Query tiered data

Set **`timescaledb.enable_tiered_reads`** (off by default) via the [service configuration](/deploy/tiger-cloud/tiger-cloud-aws/configuration/customize-configuration) or `SET` at database/session scope, then run normal `SELECT` statements.
