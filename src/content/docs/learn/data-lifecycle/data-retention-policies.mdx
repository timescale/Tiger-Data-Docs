Use [data retention policies](https://docs.timescale.com/use-timescale/latest/data-retention/create-a-retention-policy/) or [manually drop chunks](https://docs.timescale.com/use-timescale/latest/data-retention/manually-drop-chunks/) (for example “older than one year”) to bound storage and compliance scope.

## Add a policy

Attach a policy to a hypertable so chunks past a cutoff are dropped automatically. Example pattern: delete data older than **one year** on a `conditions`-style hypertable—see [create a retention policy](https://docs.timescale.com/use-timescale/latest/data-retention/create-a-retention-policy/) for exact SQL.

## Remove or pause a policy

- [`remove_retention_policy()`](https://docs.timescale.com/use-timescale/latest/data-retention/create-a-retention-policy/#remove-a-data-retention-policy) removes the policy.
- Or disable scheduling via [`alter_job()`](https://docs.timescale.com/api/latest/actions/alter_job/) with **`scheduled = false`**.

## Continuous aggregates

If you use continuous aggregates, ensure [retention does not delete raw data](https://docs.timescale.com/use-timescale/latest/data-retention/data-retention-with-continuous-aggregates/) that a CAGG refresh still needs—plan retention and refresh windows together.
