Compression reduces storage for large datasets. On Tiger Cloud, recent data is often **row-oriented** for fast wide scans; as data ages you can move it to **compressed, columnar** storage for narrower analytical queries.

## When compression helps most

- **Data changes infrequently** — Updates and deletes inside compressed chunks are supported but can be expensive.
- **Queries become deep and narrow** — You move from scanning many columns to aggregating a few over history.
- **Values repeat or sort well** — Ordered, patterned data compresses better.

## How it works

- **Chunks** — Compression runs **per chunk**, not for the whole hypertable at once.
- **Grouping** — Similar values are grouped so codecs can shrink runs of data effectively before generic compression.
