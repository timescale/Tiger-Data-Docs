## Configuration options

- **`timescaledb.compress`**: Turn compression on or off for a hypertable.
- **`timescaledb.compress_orderby`**: Row order inside compressed chunks. Often `time DESC` or `time ASC` for time-series.
- **`timescaledb.compress_segmentby`**: Segment by columns you filter or group on (for example `device_id`) to speed those queries in compressed data.
- **`timescaledb.compress_chunk_time_interval`**: Optional; rolls smaller compressed chunks into larger intervals (see [Rollup compression](#rollup-compression)).

### Choosing segmentby columns

- Prefer **lower cardinality** where it matches access patterns.
- Align with **WHERE** / **GROUP BY** usage.
- Use `count(distinct …)` and **`pg_stats`** to estimate distinct counts.

## Enable compression

Enable at the **hypertable** level, then add a **compression policy** to compress chunks on a schedule. Syntax differs before and after **2.18.0** (rowstore/columnstore APIs). Follow the version of TimescaleDB you run in Tiger Cloud; see [Compression methods](/build/columnar-storage/compression-methods) and [Set up Hypercore](/build/columnar-storage/setup-hypercore) for current commands.

Typical pattern: `ALTER TABLE` … `SET (timescaledb.compress, timescaledb.compress_segmentby = '…', timescaledb.compress_orderby = '…')`, then `add_compression_policy(...)`.

## Testing compression

1. **Pick a test chunk**: Older, cold chunks are safer. Use `show_chunks()` (for example chunks older than a few days).
2. **Baseline queries**: Run representative queries with `EXPLAIN ANALYZE` and record timings.
3. **Set compression options**: `ALTER TABLE` with segmentby/orderby.
4. **Compress manually**: `compress_chunk()` (or the 2.18+ equivalent) on the test chunk.
5. **Measure ratio**: `chunk_compression_stats()` for before/after sizes.
6. **Re-run queries**: Compare latency; validate filters on **segmentby**.
7. **Iterate**: Decompress (`decompress_chunk()` / `convert_to_rowstore` depending on version), adjust options, repeat.

## Rollup compression

Rollup (2.9+) merges smaller uncompressed chunks into larger compressed chunks.

1. Set **`compress_chunk_time_interval`** as a multiple of the uncompressed chunk interval (for example 2× or 6× the chunk size).
2. For rollup efficiency, prefer **`compress_orderby = 'time ASC'`** if the default `time DESC` causes extra recompression work.
3. Let the policy run; monitor storage and query behavior.

**Caveats:** Interval must be a **multiple** of the raw chunk interval; best when you have **many small** chunks.

## Disable compression

1. Remove the **compression policy** (stop background compression).
2. **Decompress** all affected chunks.
3. Disable compression on the hypertable.
