## Overview

In this tutorial, you learn how to use the [Tiger Data Terraform provider][terraform-provider] to create and manage {C.SERVICE_LONG}s using infrastructure as code (IaC). This tutorial is for developers and DevOps engineers who want to automate their {C.CLOUD_LONG} deployments. It assumes you have basic knowledge of:

- Terraform concepts (providers, resources, outputs)
- Command-line interfaces
- {C.CLOUD_LONG} services

By the end, you'll be able to:

- Configure the Tiger Data Terraform provider with credentials
- Deploy a {C.SERVICE_LONG} using a Terraform configuration
- Retrieve service connection details, including the password, using Terraform outputs

## Background

Terraform is an infrastructure-as-code tool that lets you declaratively configure cloud resources. Your cloud infrastructure becomes a one-to-one representation of your configuration files, which improves security, auditability, and deployment speed.

The Tiger Data Terraform provider brings these benefits to {C.CLOUD_LONG}, letting you create, configure, and destroy services without using the UI.

<Callout variant="tip">
  As of the Terraform provider v1.2.0, you can also create {C.READ_REPLICA}s
  with Terraform. This means you can automatically provision or remove
  {C.READ_REPLICA}s — for example, to spin up a replica for a business analyst
  to run BI queries against.
</Callout>

## What is the tech stack we're working with?

**Terraform:** An open-source infrastructure-as-code tool by HashiCorp that lets you define and provision cloud infrastructure using declarative configuration files. Terraform's idempotent nature means you can re-run deployments safely — if something goes wrong, re-running `terraform apply` brings your infrastructure back to the desired state.

- **Tiger Data Terraform provider:** The [official provider][terraform-provider] in the Terraform Registry (`timescale/timescale`) that lets you manage {C.SERVICE_LONG}s, VPC connections, and {C.READ_REPLICA}s.

## Prerequisites

Before you start, make sure you have:

- A [{C.ACCOUNT_LONG}](/get-started/create-service)
- [Terraform installed][terraform-install] on your local machine
- Your {C.CLOUD_LONG} Project ID and client credentials ([how to create credentials][generate-credentials])

<Callout variant="warning">
  Store your credentials securely. Never commit them to version control. For
  production use, consider HashiCorp Vault, Terraform environment variables, or
  a cloud KMS solution.
</Callout>

## Configure the Terraform provider

Set up the Tiger Data Terraform provider and authenticate with your {C.CLOUD_LONG} project.

<NumberedList>
  <NumberedItem title="Declare the provider">

Create a `main.tf` file and add the provider declaration. Set the source to `timescale/timescale` to use the official provider from the Terraform Registry:

```hcl
terraform {
  required_providers {
    timescale = {
      source  = "timescale/timescale"
      version = "~> 1.0"
    }
  }
}
```

Using the `~>` operator pins to the latest compatible minor version.

  </NumberedItem>

  <NumberedItem title="Configure provider credentials">

Add the provider configuration block to `main.tf`:

```hcl
provider "timescale" {
  project_id = var.ts_project_id
  access_key = var.ts_access_key
  secret_key = var.ts_secret_key
}
```

  </NumberedItem>

  <NumberedItem title="Define the credential variables">

Create a `variables.tf` file to declare the input variables:

```hcl
variable "ts_project_id" {
  type        = string
  description = "Tiger Cloud project ID"
}

variable "ts_access_key" {
  type        = string
  description = "Tiger Cloud access key"
}

variable "ts_secret_key" {
  type        = string
  sensitive   = true
  description = "Tiger Cloud secret key"
}
```

Then create a `terraform.tfvars` file or export environment variables to supply the values:

```bash
export TF_VAR_ts_project_id="<your-project-id>"
export TF_VAR_ts_access_key="<your-access-key>"
export TF_VAR_ts_secret_key="<your-secret-key>"
```

<Callout variant="tip">
  To find your Project ID, go to the Services tab in {C.CONSOLE} and click the
  kebab menu (⋮) in the top-right corner. To create credentials, go to **Project
  Settings** and click **Create credentials**. Copy both the public and private
  keys to a secure location — this is the only time you can retrieve them.
</Callout>

  </NumberedItem>
</NumberedList>

## Create a service

Define and deploy a {C.SERVICE_LONG} using your Terraform configuration.

<NumberedList>
  <NumberedItem title="Add the service resource">

Add a `timescale_service` resource to your `main.tf` file:

```hcl
resource "timescale_service" "my_service" {
  name        = "my-service"
  milli_cpu   = 1000
  memory_gb   = 4
  region_code = "us-east-1"

  lifecycle {
    prevent_destroy = true
  }
}
```

This creates a service with 1 CPU and 4 GB of memory in `us-east-1`. Only specific CPU and memory combinations are supported — consult the [provider documentation][terraform-provider] for details.

{C.CLOUD_LONG} automatically allocates and charges only for the storage you use, so you don't need to pre-provision a specific storage size.

<Callout variant="warning">
  The `prevent_destroy` lifecycle rule is highly recommended. If a
  {C.SERVICE_LONG} is destroyed, the data it stores is destroyed too. Remove or
  comment out the lifecycle block only when you intentionally want to delete the
  service and its data.
</Callout>

  </NumberedItem>

  <NumberedItem title="Initialize and deploy">

Run the following commands in order:

```bash
terraform init
terraform plan
terraform apply
```

Terraform shows you the planned changes. Enter `yes` when prompted to confirm:

```
Plan: 1 to add, 0 to change, 0 to destroy.

Do you want to perform these actions?
  Terraform will perform the actions described above.
  Only 'yes' will be accepted to approve.

  Enter a value: yes

timescale_service.my_service: Creating...
timescale_service.my_service: Creation complete after 38s

Apply complete! Resources: 1 added, 0 changed, 0 destroyed.
```

  </NumberedItem>
</NumberedList>

## Retrieve service connection details

After deploying the service, use Terraform outputs to retrieve the connection details, including the password.

<NumberedList>
  <NumberedItem title="Define the outputs">

Create an `outputs.tf` file:

```hcl
output "service_hostname" {
  value = timescale_service.my_service.hostname
}

output "service_port" {
  value = timescale_service.my_service.port
}

output "service_username" {
  value = timescale_service.my_service.username
}

output "service_password" {
  value     = timescale_service.my_service.password
  sensitive = true
}
```

  </NumberedItem>

  <NumberedItem title="Apply and retrieve the outputs">

Re-apply and then view the outputs:

```bash
terraform apply
terraform output
```

Terraform shows the hostname, port, and username, but keeps the password hidden because it is marked `sensitive`. To retrieve the password, use the `-json` flag:

```bash
terraform output -json | jq -r ".service_password.value"
```

  </NumberedItem>

  <NumberedItem title="(Optional) Synthesize a full connection string">

You can compose the full connection string as a Terraform output. This is useful when other Terraform resources need to connect to your {C.SERVICE_LONG}:

```hcl
output "service_url" {
  value = format(
    "postgres://%s:%s@%s:%s/tsdb?sslmode=require",
    timescale_service.my_service.username,
    timescale_service.my_service.password,
    timescale_service.my_service.hostname,
    timescale_service.my_service.port
  )
  sensitive = true
}
```

  </NumberedItem>
</NumberedList>
