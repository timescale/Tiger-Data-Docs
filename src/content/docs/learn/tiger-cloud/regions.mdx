# Supported regions

{C.CLOUD_LONG} is available on Amazon Web Services (AWS) and Microsoft Azure. You select a cloud
provider and region when you create a {C.SERVICE_SHORT}. The region determines where your data is
stored and where your compute runs, which affects query latency and data residency.

## Choosing a region

When selecting a region for your {C.SERVICE_SHORT}, consider:

- **Proximity to your application**: choose a region close to your application servers or end users
  to minimize network latency.
- **Data residency requirements**: regulatory or compliance requirements may dictate where your
  data must be stored. For example, GDPR requirements may require EU-based storage.
- **Cloud provider alignment**: if your application infrastructure already runs on AWS or Azure,
  choosing the same provider and region reduces data transfer costs and latency.
- **Feature availability**: some features, such as VPC peering and AWS Transit Gateway, are
  available on specific cloud providers. See the [feature comparison](/get-started/feature-comparison)
  for details.

## Cross-region backups

On AWS, {C.CLOUD_LONG} supports cross-region backups, allowing you to store backup copies of your
data in a different AWS region from your primary {C.SERVICE_SHORT}. This provides additional
protection against regional outages.
