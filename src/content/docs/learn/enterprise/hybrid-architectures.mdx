Some teams that keep their database on infrastructure they operate themselves still want the reach
of a managed cloud for parts of their workload, such as cross-site reporting or elastic analytics
capacity. Cloud Sync is built for that: it optionally replicates data from a TimescaleDB Enterprise
cluster to {C.CLOUD_LONG}, so your system of record stays on infrastructure you control while
analytics, dashboards, or cross-site queries can run against the {C.CLOUD_LONG} copy.

## Why hybrid instead of one or the other

Choosing self-managed infrastructure is usually driven by requirements a managed cloud cannot
satisfy: data sovereignty, air-gap, or an existing on-premises footprint. Those requirements apply
to where the primary database lives, not necessarily to every downstream consumer of that data.
Cloud Sync lets you keep the primary database on infrastructure that meets those requirements while
still giving other parts of the business, such as centralized reporting across multiple sites, the
elasticity of {C.CLOUD_LONG}.

## The pattern

Your TimescaleDB Enterprise cluster remains the system of record. Cloud Sync streams a copy to a
{C.CLOUD_LONG} destination you choose, alongside your existing on-premises workload, without
changing how applications write to the primary cluster.

Cloud Sync is the only component in TimescaleDB Enterprise that connects outward. Fully air-gapped
deployments can leave it disabled and still use every other capability of the product.

To turn on replication for a cluster, see
[Configure Cloud Sync](/deploy/enterprise/cloud-sync).
