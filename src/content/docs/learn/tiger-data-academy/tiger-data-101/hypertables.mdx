## Knowledge Check

### Question 1

When you query a {C.HYPERTABLE} with a time filter (e.g., `WHERE time > NOW() - INTERVAL '7 days'`), what optimization does {C.TIMESCALE_DB} apply automatically?

- A) It scans all chunks in parallel for maximum throughput
- B) It only reads the chunks that overlap with the time range (chunk exclusion)
- C) It decompresses matching rows before returning them
- D) It routes the query only to the most recently written chunk

### Question 2

Which function call converts an existing PostgreSQL table into a hypertable?

- A) `ALTER TABLE ... ENABLE TIMESCALE`
- B) `partition_table_by_time()`
- C) `create_hypertable()`
- D) `SET timescaledb.hypertable = true`

### Question 3

By default, {C.TIMESCALE_DB} automatically partitions hypertables along which dimension?

- A) Row count (chunk when N rows are reached)
- B) Primary key range
- C) Time
- D) Alphabetical order of the first indexed column

---

## Answers

| # | Answer | Explanation |
| --- | --- | --- |
| 1 | **B** | {C.TIMESCALE_DB} uses chunk exclusion to skip all chunks whose time range does not overlap the query filter, so only relevant data is scanned |
| 2 | **C** | `create_hypertable('table_name', by_range('time'))` converts a regular table into a hypertable |
| 3 | **C** | Time is the primary partitioning dimension; a second dimension (e.g., device ID) can be added for space partitioning |
