### Question 1

Kempower, an EV charging hardware manufacturer, migrated to {C.CLOUD_LONG}} and achieved approximately what storage footprint reduction using {C.HYPERCORE} compression?

- A) 2x
- B) 5x
- C) 15x
- D) 100x

### Question 2

Which {C.HYPERCORE} compression method is specifically optimized for floating-point time-series values like temperature sensor readings?

- A) Dictionary encoding
- B) Array encoding
- C) Delta encoding
- D) Gorilla compression

### Question 3

What is the key advantage of being able to mix compressed (cold) and uncompressed (hot) chunks in the same hypertable?

- A) Compressed chunks support faster writes than uncompressed chunks
- B) Recent data stays uncompressed for fast writes while older data is compressed for storage savings, with no schema changes
- C) Each team member can independently choose which chunks to compress
- D) Compressed chunks are automatically geo-replicated across regions

---

## Answers

| # | Answer | Explanation |
| --- | --- | --- |
| 1 | **C** | Kempower achieved a 15x storage reduction after migrating historical EV charging session data to {C.CLOUD_LONG}} with {C.HYPERCORE} compression |
| 2 | **D** | Gorilla compression (from Facebook's Gorilla paper) is designed for floating-point time-series data and achieves very high compression ratios |
| 3 | **B** | {C.TIMESCALE_DB} automatically applies compression to older chunks via policy while leaving recent chunks uncompressed; the hypertable interface stays identical to the application |
