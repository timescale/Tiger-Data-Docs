## Creating a Continuous Aggregate

> TODO: Content coming soon.

```sql
CREATE MATERIALIZED VIEW hourly_sensor_summary
WITH (timescaledb.continuous) AS
SELECT
  time_bucket('1 hour', time) AS bucket,
  device_id,
  avg(temperature) AS avg_temperature,
  max(temperature) AS max_temperature,
  min(temperature) AS min_temperature
FROM sensor_readings
GROUP BY bucket, device_id
WITH NO DATA;

-- Add a refresh policy
SELECT add_continuous_aggregate_policy('hourly_sensor_summary',
  start_offset => INTERVAL '3 hours',
  end_offset   => INTERVAL '1 hour',
  schedule_interval => INTERVAL '1 hour'
);
```

## Knowledge Check

### Question 1

What SQL object does a Continuous Aggregate most closely resemble in standard PostgreSQL?

- A) A stored procedure
- B) A trigger
- C) A materialized view
- D) A partial index

### Question 2

When new data is inserted into a time bucket that a CAGG has already processed, what mechanism marks that bucket for re-computation on the next refresh?

- A) A cron job that scans the hypertable every minute
- B) Invalidation tracking
- C) A mandatory manual `REFRESH MATERIALIZED VIEW` call
- D) Row-level triggers attached to the hypertable

### Question 3

A team serves hourly, daily, and monthly rollups from a single dataset. What is the most efficient approach in {C.TIMESCALE_DB}?

- A) Run three separate GROUP BY queries against the raw hypertable on each request
- B) Hierarchical CAGGs: the daily CAGG reads from the hourly CAGG, the monthly from the daily
- C) Export data nightly to a data warehouse for daily and monthly queries
- D) Create three separate hypertables, one per granularity

---

## Answers

| # | Answer | Explanation |
| --- | --- | --- |
| 1 | **C** | A Continuous Aggregate is a specialized materialized view with automatic incremental refresh; {C.TIMESCALE_DB} only recomputes the buckets that have changed |
| 2 | **B** | {C.TIMESCALE_DB}'s invalidation log tracks which time buckets have been modified. On the next refresh run, only those buckets are recomputed |
| 3 | **B** | Hierarchical CAGGs avoid re-scanning raw data: the daily CAGG reads pre-aggregated hourly results, and the monthly reads from daily; each level only does incremental work |
