High-ingest workloads need aggregates that blend historical rollups with the live tail without blocking writers.

By default, {C.CAGG}s do not include the most recent data {C.CHUNK} from the
underlying {C.HYPERTABLE}. {C.RTAGG_CAP}s, however, use the aggregated data **and** add the
most recent raw data to it. This provides accurate and up-to-date results, without
needing to aggregate data as it is being written.

<RealTimeAgg />

For more detail on the comparison between {C.CAGG}s and {C.RTAGG}s,
see the [{C.RTAGG} blog post](https://tigerdata.com/blog/achieving-the-best-of-both-worlds-ensuring-up-to-date-results-with-real-time-aggregation/).

## Use {C.RTAGG}s

You can enable and disable real-time aggregation by setting the
`materialized_only` parameter when you create or alter the view.

<NumberedList>
<NumberedItem title="Enable real-time aggregation">
```sql
ALTER MATERIALIZED VIEW table_name set (timescaledb.materialized_only = false);
```
</NumberedItem>

<NumberedItem title="Disable real-time aggregation">
```sql
ALTER MATERIALIZED VIEW table_name set (timescaledb.materialized_only = true);
```
</NumberedItem>
</NumberedList>
