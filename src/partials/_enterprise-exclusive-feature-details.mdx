{C.TDB_COMMUNITY} is the open-source {C.TIMESCALE_DB} engine you install and operate yourself.
TimescaleDB Enterprise runs the same engine and adds a managed control plane for the operational
work that would otherwise be yours to build and maintain. This page covers what that control plane
adds. For what the product is and who it is for, see
[Meet TimescaleDB Enterprise](/learn/enterprise).

TimescaleDB Enterprise adds:

- **High availability**: automatic failover across a database cluster.
- **Automated backups**: scheduled incremental backups with point-in-time restore.
- **Low-downtime upgrades**: console-coordinated {C.PG} and {C.TIMESCALE_DB} upgrades.
- **Built-in monitoring**: pre-configured dashboards for cluster health.
- **Cloud Sync**: optional replication to {C.CLOUD_LONG}.
- **Enterprise support**: commercial support with SLA-backed response times.

## High availability

TimescaleDB Enterprise runs your database as a cluster with automatic failover. If a node goes down,
the console promotes a standby and reroutes connections, so the database keeps serving without
manual intervention.

This is high availability for infrastructure you own and run yourself, which isn't the same as
failover in a managed cloud: the hardware and network stay with you, and TimescaleDB Enterprise
takes care of the coordination.

## Automated backups

Incremental backups run on a schedule or on demand, and you can restore to any point in time.
Recovery is a console operation: pick a target time and restore, without keeping your own backup
scripts alive. Backups can be directed to a dedicated host.

## Low-downtime upgrades

You upgrade {C.PG} and {C.TIMESCALE_DB} versions from the console. Upgrades are coordinated across
the cluster to keep downtime low, which helps when the database backs a site that can't easily
schedule an outage.

## Built-in monitoring

TimescaleDB Enterprise comes with pre-configured dashboards for cluster health, so you can see
resource usage and database activity without setting up a separate metrics stack.

## Cloud Sync

Cloud Sync optionally replicates data to {C.CLOUD_LONG}, so you can keep your system of record on
your own infrastructure and still run cross-site or cloud analytics. It's the only component that
connects outward, so air-gapped deployments can leave it disabled. For the thinking behind combining
self-managed infrastructure with {C.CLOUD_LONG} this way, see
[Hybrid architectures with Cloud Sync](/learn/enterprise/hybrid-architectures).

## Enterprise support

TimescaleDB Enterprise includes commercial support with direct engineer access and SLA-backed
response times, which often matters most for teams running critical workloads they can't outsource.
