When you create a {C.SERVICE_SHORT}, {C.CLOUD_LONG} assigns you the tsdbadmin role. This role has full permissions to modify data in your {C.SERVICE_SHORT}. However, {C.CLOUD_LONG} does not provide superuser access. tsdbadmin is not a superuser.

As tsdbadmin, you can use standard {C.PG} means to create other roles or assign individual permissions. This page shows you how to create a read-only role for your database. Adding a read-only role does not provide resource isolation. To restrict the access of a read-only user, as well as isolate resources, create a [read replica](../high-availability/read-scaling) instead.

<Callout variant="note">

This page covers database-level roles only. {C.CLOUD_LONG} restricts access in two other places, neither of which overlaps with these roles:

- To stop {C.CLI_LONG}, {C.MCP_LONG}, and the AI agents that use them from making changes, turn on the [`read_only` option](/reference/tiger-cloud/tiger-cli#configuration-parameters). For when to use it, see [best practices for AI agents](/build/tiger-cli-mcp/agent-best-practices#restrict-agents-to-read-only).
- To control who can sign in to your {C.PROJECT_SHORT} and what they can do there, see [Control user access to {C.PROJECT_LONG}s](../security/members).

</Callout>

## Create a read-only user

You can create a read-only user to provide limited access to your database.

<NumberedList>

<NumberedItem title={`Connect to your ${C.SERVICE_SHORT} as the tsdbadmin user`}>

</NumberedItem>

<NumberedItem title="Create the new role">

```sql
CREATE ROLE <ROLE_NAME>;
```

</NumberedItem>

<NumberedItem title="Grant usage on the schema to allow access to objects within it">

```sql
GRANT USAGE ON SCHEMA <SCHEMA_NAME> TO <ROLE_NAME>;
```

</NumberedItem>

<NumberedItem title="Grant the appropriate permissions for the role, as required">

For example, to grant `SELECT` permissions to a specific table, use:

```sql
GRANT SELECT ON <TABLE_NAME> TO <ROLE_NAME>;
```

To grant `SELECT` permissions to all tables in a specific schema, use:

```sql
GRANT SELECT ON ALL TABLES IN SCHEMA <SCHEMA_NAME> TO <ROLE_NAME>;
```

</NumberedItem>

<NumberedItem title="Create a new user">

```sql
CREATE USER <USERNAME> WITH PASSWORD '<PASSWORD>';
```

</NumberedItem>

<NumberedItem title="Assign the role to the new user">

```sql
GRANT <ROLE_NAME> TO <USERNAME>;
```

</NumberedItem>

</NumberedList>
