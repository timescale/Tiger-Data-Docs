To manage development forks:

<NumberedList>

<NumberedItem title={`Fork the ${C.SERVICE_SHORT}`}>

```shell
 tiger service fork tgrservice --now --no-wait --name bob
```
You must specify exactly one timing option: `--now` (fork at current state), `--last-snapshot` (fork at last snapshot, faster), or `--to-timestamp` (fork at specific point in time). By default a fork matches the resources of the parent {C.SERVICE_LONG}. For standard {C.SERVICE_SHORT}s, specify `--cpu` and/or `--memory` for dedicated resources.

<NumberedItem title={`When you are done, delete your forked ${C.SERVICE_SHORT}`}>

1. Use the CLI to request {C.SERVICE_SHORT} delete:

   ```shell
   tiger service delete <service_id>
   ```

1. Validate the {C.SERVICE_SHORT} delete:

   ```text
   Are you sure you want to delete service '<service_id>'? This operation cannot be undone.
   Type the service ID '<service_id>' to confirm:
   <service_id>
   ```

   You see something like:

   ```text
   🗑️  Delete request accepted for service '<service_id>'.
   ✅ Service '<service_id>' has been successfully deleted.
   ```

</NumberedItem>
