Replica identity assists data replication by identifying the rows being modified. Your options are that each table and hypertable in the source database should either have:

<ul>
<li><strong>A primary key</strong>: data replication defaults to the primary key of the table being replicated. Nothing to do.</li>
<li><strong>A viable unique index</strong>: each table has a unique, non-partial, non-deferrable index that includes only columns marked as <code>NOT NULL</code>. If a UNIQUE index does not exist, create one to assist the migration. You can delete it after migration. For each table, set <code>REPLICA IDENTITY</code> to the viable unique index:<pre><code>psql -X -d $SOURCE -c 'ALTER TABLE &lt;table name&gt; REPLICA IDENTITY USING INDEX &lt;_index_name&gt;'</code></pre></li>
<li><strong>No primary key or viable unique index</strong>: use brute force. For each table, set <code>REPLICA IDENTITY</code> to <code>FULL</code>:<pre><code>psql -X -d $SOURCE -c 'ALTER TABLE &lt;table_name&gt; REPLICA IDENTITY FULL'</code></pre>For each <code>UPDATE</code> or <code>DELETE</code> statement, {C.PG} reads the whole table to find all matching rows. This results in significantly slower replication. If you are expecting a large number of <code>UPDATE</code> or <code>DELETE</code> operations on the table, best practice is to not use <code>FULL</code>.</li>
</ul>
