[{C.REST_LONG}](/reference/tiger-cloud-rest) is a comprehensive RESTful API you use to manage {C.CLOUD_LONG} resources
including VPCs, {C.SERVICE_SHORT}s, and read replicas.

This page shows you how to set up secure authentication for the {C.REST_LONG} and create your first {C.SERVICE_SHORT}.

## Prerequisites

<RESTPrereqs />

* Install [curl](https://curl.se/).


## Configure secure authentication

{C.REST_LONG} uses HTTP Basic Authentication with access keys and secret keys. All API requests must include
proper authentication headers.

<NumberedList>

<NumberedItem title="Set up API credentials">

1. In {C.CONSOLE} [copy your project ID](/integrate/find-connection-details/#find-your-project-and-service-id) and store it securely using an environment variable:

   ```bash
   export TIGERDATA_PROJECT_ID="your-project-id"
   ```

 1. In {C.CONSOLE} [create your client credentials](/integrate/find-connection-details/#create-client-credentials) and store them securely using environment variables:

    ```bash
    export TIGERDATA_ACCESS_KEY="Public key"
    export TIGERDATA_SECRET_KEY="Secret key"
    ```

</NumberedItem>

<NumberedItem title="Configure the API endpoint">

Set the base URL in your environment:

 ```bash
 export API_BASE_URL="https://console.cloud.tigerdata.com/public/api/v1"
 ```

</NumberedItem>

<NumberedItem title={`Test your authenticated connection to ${C.REST_LONG} by listing the ${C.SERVICE_SHORT}s in the current ${C.PROJECT_LONG}`}>

```bash
 curl -X GET "${API_BASE_URL}/projects/${TIGERDATA_PROJECT_ID}/services" \
   -u "${TIGERDATA_ACCESS_KEY}:${TIGERDATA_SECRET_KEY}" \
   -H "Content-Type: application/json"
 ```

This call returns something like:
 - No {C.SERVICE_SHORT}s:
   ```txt
   []%
   ```
 - One or more {C.SERVICE_SHORT}s:

   ```txt
   [{"service_id":"tgrservice","project_id":"tgrproject","name":"tiger-eon",
   "region_code":"us-east-1","service_type":"TIMESCALEDB",
   "created":"2025-10-20T12:21:28.216172Z","paused":false,"status":"READY",
   "resources":[{"id":"104977","spec":{"cpu_millis":500,"memory_gbs":2,"volume_type":""}}],
   "metadata":{"environment":"DEV"},
   "endpoint":{"host":"tgrservice.tgrproject.tsdb.cloud.timescale.com","port":11111}}]
   ```

</NumberedItem>

</NumberedList>


## Create your first {C.SERVICE_LONG}

Create a new {C.SERVICE_SHORT} using the {C.REST_LONG}:

<NumberedList>

<NumberedItem title={`Create a ${C.SERVICE_SHORT} using the POST endpoint`}>

```bash
curl -X POST "${API_BASE_URL}/projects/${TIGERDATA_PROJECT_ID}/services" \
  -u "${TIGERDATA_ACCESS_KEY}:${TIGERDATA_SECRET_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
     "name": "my-first-service",
     "addons": ["time-series"],
     "region_code": "us-east-1",
     "replica_count": 1,
     "cpu_millis": "1000",
     "memory_gbs": "4"
     }'
```
{C.CLOUD_LONG} creates a Development environment for you. That is, no delete protection, high-availability, spooling or
read replication. You see something like:
```txt
 {"service_id":"tgrservice","project_id":"tgrproject","name":"my-first-service",
 "region_code":"us-east-1","service_type":"TIMESCALEDB",
 "created":"2025-10-20T22:29:33.052075713Z","paused":false,"status":"QUEUED",
 "resources":[{"id":"105120","spec":{"cpu_millis":1000,"memory_gbs":4,"volume_type":""}}],
 "metadata":{"environment":"PROD"},
 "endpoint":{"host":"tgrservice.tgrproject.tsdb.cloud.timescale.com","port":00001},
 "initial_password":"notTellingYou",
 "ha_replicas":{"sync_replica_count":0,"replica_count":1}}
```

</NumberedItem>

<NumberedItem title="Save `service_id` from the response to a variable:">

```bash
# Extract service_id from the JSON response
export SERVICE_ID="service_id-from-response"
```

</NumberedItem>

<NumberedItem title={`Check the configuration for the ${C.SERVICE_SHORT}`}>

```bash
 curl -X GET "${API_BASE_URL}/projects/${TIGERDATA_PROJECT_ID}/services/${SERVICE_ID}" \
   -u "${TIGERDATA_ACCESS_KEY}:${TIGERDATA_SECRET_KEY}" \
   -H "Content-Type: application/json"
```
You see something like:
```txt

 "region_code":"us-east-1","service_type":"TIMESCALEDB",
 "created":"2025-10-20T22:29:33.052075Z","paused":false,"status":"READY",
 "resources":[{"id":"105120","spec":{"cpu_millis":1000,"memory_gbs":4,"volume_type":""}}],
 "metadata":{"environment":"DEV"},
 "endpoint":{"host":"tgrservice.tgrproject.tsdb.cloud.timescale.com","port":11111},
 "ha_replicas":{"sync_replica_count":0,"replica_count":1}}
```

</NumberedItem>

</NumberedList>

And that is it, you are ready to use the [{C.REST_LONG}](/reference/tiger-cloud-rest) to manage your
{C.SERVICE_SHORT}s in {C.CLOUD_LONG}.

## Security best practices

Follow these security guidelines when working with the {C.REST_LONG}:

- **Credential management**
    - Store API credentials as environment variables, not in code
    - Use credential rotation policies for production environments
    - Never commit credentials to version control systems

- **Network security**
    - Use HTTPS endpoints exclusively for API communication
    - Implement proper certificate validation in your HTTP clients

- **Data protection**
    - Use secure storage for service connection strings and passwords
    - Implement proper backup and recovery procedures for created services
    - Follow data residency requirements for your region
