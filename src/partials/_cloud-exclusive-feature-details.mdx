## Tiered storage

{C.CLOUD_LONG} provides a [hierarchical storage architecture](/learn/data-management/storage/about-storage-tiers) with two tiers:

- **High-performance tier**: block storage optimized for fast reads and writes, available in standard
  (up to 16 TB, 16K IOPS) and enhanced (up to 64 TB, 32K IOPS) configurations.
- **Object storage tier**: low-cost, virtually unlimited storage backed by AWS S3 or Azure Blob,
  using Apache Parquet format for efficient analytical queries.

Tiering policies automate data movement between tiers based on age, so recent data stays fast
and older data stays affordable. Tiered data remains fully queryable with standard SQL. Learn how to
[manage storage](/build/data-management/storage/manage-storage) and [query tiered data](/build/data-management/storage/query-tiered-data).

## {C.HA_REPLICA_CAP}s

{C.CLOUD_LONG} supports automatic {C.HA_REPLICA}s that maintain a synchronized copy of your
{C.SERVICE_SHORT}. If the primary instance becomes unavailable, the replica is promoted automatically,
minimizing downtime. {C.HA_REPLICA_SHORT}s are available on {C.SCALE} and {C.ENTERPRISE} {C.PRICING_PLAN}s.
Learn more about high availability on [AWS](/deploy/tiger-cloud/tiger-cloud-aws/high-availability/high-availability)
or [Azure](/deploy/tiger-cloud/tiger-cloud-azure/high-availability/high-availability).

## {C.READ_REPLICA_CAP}s

Offload read-heavy workloads — dashboards, reporting queries, and analytics — to dedicated
{C.READ_REPLICA}s. {C.READ_REPLICA_CAP}s receive streaming replication from the primary and serve
read-only queries independently, which helps avoid resource contention on the primary. Set up
{C.READ_REPLICA}s on [AWS](/deploy/tiger-cloud/tiger-cloud-aws/high-availability/read-scaling)
or [Azure](/deploy/tiger-cloud/tiger-cloud-azure/high-availability/read-scaling).

## Built-in observability

{C.CONSOLE} provides observability tools without requiring additional monitoring infrastructure:

- **Insights**: analyze query performance, identify slow queries, and understand resource
  utilization patterns directly from {C.CONSOLE}.
- **Service metrics**: monitor CPU, memory, storage, and connection usage with built-in dashboards.
- **External integrations**: export metrics to CloudWatch, Datadog, Prometheus, or Azure Monitor to
  integrate with your existing monitoring stack.

Learn more about monitoring on [AWS](/deploy/tiger-cloud/tiger-cloud-aws/monitoring)
or [Azure](/deploy/tiger-cloud/tiger-cloud-azure/monitoring).

## Data connectors

{C.CLOUD_LONG} provides built-in connectors for ingesting and exporting data:

- **[{C.PG_CONNECTOR_CAP}](/integrate/connectors/source/sync-from-postgres)**: replicate data from an external {C.PG} database into your {C.SERVICE_SHORT}.
- **[{C.S3_CONNECTOR_CAP}](/integrate/connectors/source/sync-from-s3)**: import data from CSV and Parquet files stored in Amazon S3.
- **[Kafka connector](/integrate/connectors/source/sync-from-kafka)**: stream data from Apache Kafka topics directly into {C.HYPERTABLE}s.
- **[{C.LAKE_SHORT}](/integrate/connectors/destination/tigerlake)**: export data from {C.CLOUD_LONG} to Apache Iceberg tables for lakehouse
  analytics workflows.

<Callout variant="note">
Connector availability varies by cloud provider and {C.PRICING_PLAN}. See the
[feature comparison](/get-started/feature-comparison) for details.
</Callout>

## Managed security and compliance

{C.CLOUD_LONG} includes security features managed at the platform level:

- **Encryption**: data is encrypted at rest and in transit by default.
- **Network isolation**: [{C.VPC} peering](/deploy/tiger-cloud/tiger-cloud-aws/security/vpc) (AWS),
  [AWS Transit Gateway](/deploy/tiger-cloud/tiger-cloud-aws/security/transit-gateway), and
  [Azure Private Link](/deploy/tiger-cloud/tiger-cloud-azure/security/azure-privatelink)
  provide private connectivity between your application and {C.SERVICE_SHORT}.
- **SOC 2 compliance**: {C.CLOUD_LONG} is SOC 2 Type II certified.

Learn more about security on [AWS](/deploy/tiger-cloud/tiger-cloud-aws/security/overview)
or [Azure](/deploy/tiger-cloud/tiger-cloud-azure/security/overview).

## Automated operations

{C.CLOUD_LONG} manages the operational overhead of running a production database:

- **Automated backups**: continuous backups with point-in-time recovery (PITR). See backup and restore on
  [AWS](/deploy/tiger-cloud/tiger-cloud-aws/high-availability/backup-restore) or
  [Azure](/deploy/tiger-cloud/tiger-cloud-azure/high-availability/backup-restore).
- **Upgrades**: {C.PG} major version upgrades, {C.TIMESCALE_DB} updates, and security patches
  are applied automatically with minimal disruption. See upgrades on
  [AWS](/deploy/tiger-cloud/tiger-cloud-aws/upgrades) or
  [Azure](/deploy/tiger-cloud/tiger-cloud-azure/upgrades).
- **Scaling**: resize compute and storage independently through {C.CONSOLE} or the {C.REST_LONG}. See scaling on
  [AWS](/deploy/tiger-cloud/tiger-cloud-aws/service-management/change-resources) or
  [Azure](/deploy/tiger-cloud/tiger-cloud-azure/service-management/change-resources).
