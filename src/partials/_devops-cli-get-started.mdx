{C.CLI_LONG} is a command-line interface that you use to manage {C.CLOUD_LONG} resources
including VPCs, services, read replicas, and related infrastructure. {C.CLI_LONG} calls {C.REST_LONG} to communicate with
{C.CLOUD_LONG}.

This page shows you how to install and set up secure authentication for {C.CLI_LONG}, then create your first
service. You don't need a {C.ACCOUNT_LONG} beforehand: if you don't have one, you can sign up when you log in during setup.

## Create your first {C.SERVICE_LONG}

Create a new {C.SERVICE_LONG} using {C.CLI_LONG}:

<NumberedList>

<NumberedItem title={`Submit a ${C.SERVICE_SHORT} creation request`}>

The default {C.SERVICE_SHORT} configuration depends on your plan: paid plans create a 0.5 CPU, 2 GB {C.SERVICE_SHORT} with the `time-series` capability, while the free plan uses shared CPU and memory and enables the `time-series` and `ai` capabilities.

```shell
tiger service create
```
To control the {C.SERVICE_SHORT} configuration, use the [`service create` flags](/reference/tiger-cloud/tiger-cli). For
example, create a free service with `tiger service create --cpu shared`, or set capabilities with `--addons time-series,ai`.

<FreeBeta />

Free services with shared CPU/memory are only available in the `us-east-1` region. Standard services can be created in any available AWS or Azure region using the `--region` flag.
