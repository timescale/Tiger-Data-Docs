Updating parameters on a {C.PG} instance will cause an outage. Choose a time that will cause the least issues to tune this database.

<NumberedList>
<NumberedItem title="Update the DB instance parameter group for your source database">

<ol type="a">
<li>

In [https://console.aws.amazon.com/rds/home#databases:](https://console.aws.amazon.com/rds/home#databases:),
select the RDS instance to migrate.

</li>
<li>

Click `Configuration`, scroll down and note the `DB instance parameter group`, then click `Parameter groups`

<Image src={imgParameterGroups} alt="RDS parameter groups in the AWS console" />

</li>
<li>

Click `Create parameter group`, fill in the form with the following values, then click `Create`.

- **Parameter group name** - whatever suits your fancy.
- **Description** - knock yourself out with this one.
- **Engine type** - `{C.PG}`
- **Parameter group family** - the same as `DB instance parameter group` in your `Configuration`.

</li>
<li>In `Parameter groups`, select the parameter group you created, then click `Edit`.</li>
<li>

Update the following parameters, then click `Save changes`.

- `rds.logical_replication` set to `1`: record the information needed for logical decoding.
- `wal_sender_timeout` set to `0`: disable the timeout for the sender process.

</li>
<li>In RDS, navigate back to your [databases](https://console.aws.amazon.com/rds/home#databases:), select the RDS instance to migrate, and click `Modify`.</li>
<li>Scroll down to `Database options`, select your new parameter group, and click `Continue`.</li>
<li>

Click `Apply immediately` or choose a maintenance window, then click `Modify DB instance`.

Changing parameters will cause an outage. Wait for the database instance to reboot before continuing.

</li>
<li>Verify that the settings are live in your database.</li>
</ol>
</NumberedItem>
