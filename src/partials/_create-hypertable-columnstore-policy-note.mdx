When you create a {C.HYPERTABLE} using [CREATE TABLE ... WITH ...](/reference/timescaledb/), the default partitioning
column is automatically the first column with a timestamp data type. Also, {C.TIMESCALE_DB} creates a
[columnstore policy](/reference/timescaledb/) that automatically converts your data to the {C.COLUMNSTORE}, after an interval equal to the value of the [chunk_interval](/reference/timescaledb/), defined through `compress_after` in the policy. This columnar format enables fast scanning and
aggregation, optimizing performance for analytical workloads while also saving significant storage space. In the
{C.COLUMNSTORE} conversion, {C.HYPERTABLE} chunks are compressed by up to 98%, and organized for efficient, large-scale queries.

You can customize this policy later using [alter_job](/reference/timescaledb/). However, to change `after` or
`created_before`, the compression settings, or the {C.HYPERTABLE} the policy is acting on, you must
[remove the columnstore policy](/reference/timescaledb/) and [add a new one](/reference/timescaledb/).

You can also manually [convert chunks](/reference/timescaledb/) in a {C.HYPERTABLE} to the {C.COLUMNSTORE}.
