**Table sync status**

```bash
psql "$TARGET" -c "
  SELECT state, last_error, count(*)
  FROM _ts_live_sync.subscription_rel
  GROUP BY 1, 2 ORDER BY 1, 2;
"
```

Tables with errors appear as separate rows grouped by `last_error`.

| State | Meaning |
| --- | --- |
| `i` | Initial state; table data sync not started. |
| `d` | Initial table data sync is in progress. |
| `f` | Initial table data sync completed; catching up with incremental changes. |
| `s` | Synchronized; waiting for the main apply worker to take over. |
| `r` | Table is ready; applying changes in real time. |

**COPY progress during initial sync**

Monitor that the initial data copy is progressing as expected. The number of rows returned should usually match the `--table-sync-workers` value.

```bash
psql "$SOURCE" -c "SELECT * FROM pg_stat_progress_copy;"
```

**Replication lag**

On the source using `pg_replication_slots`:

```bash
psql "$SOURCE" -c "
  SELECT slot_name,
    pg_size_pretty(pg_current_wal_flush_lsn() - confirmed_flush_lsn) AS lag
  FROM pg_replication_slots
  WHERE slot_name LIKE 'live_sync_%' AND slot_type = 'logical';
"
```

On the target using `_ts_live_sync.subscription` (also shows `last_error` if any):

```bash
psql "$TARGET" -c "
  SELECT
    pg_size_pretty(source_flush_lsn - last_replicated_lsn) AS lag_bytes,
    now() - last_replicated_txn_time AS replication_lag,
    now() - metrics_updated_at AS last_progress_age,
    now() - updated_at AS heartbeat_age,
    *
  FROM _ts_live_sync.subscription;
"
```

The connector writes `last_replicated_txn_time`, `metrics_updated_at`, and `updated_at`. If
the connector hangs, all three freeze, so compare them against the target's `now()`, which
keeps advancing:

- `replication_lag`: time since the last replicated transaction committed at the source. It
  grows whenever replication stalls, and it also grows while the source is idle.
- `last_progress_age`: time since the connector last updated `last_replicated_txn_time`. A low
  value means replication is moving. The timestamp uses the connector clock, so clock skew
  can make it drift.
- `heartbeat_age`: time since the connector last wrote these metrics to the subscription
  catalog table. The connector refreshes it about every 30 seconds, even with no new
  transactions. It grows only when the connector is hung or stopped. If `last_progress_age`
  grows but `heartbeat_age` stays low, the connector runs but is stuck, often on a large
  operation.
