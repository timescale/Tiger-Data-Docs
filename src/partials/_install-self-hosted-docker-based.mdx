<NumberedItem title={`Run the ${C.TIMESCALE_DB} Docker image`}>

The [{C.TIMESCALE_DB} HA](https://hub.docker.com/r/timescale/timescaledb-ha) Docker image offers the most complete
{C.TIMESCALE_DB} experience. It uses [Ubuntu](https://ubuntu.com), includes
[{C.TOOLKIT_LONG}](https://github.com/timescale/timescaledb-toolkit), and support for PostGIS and Patroni.

To install the latest release based on {C.PG} 18:

```
docker pull timescale/timescaledb-ha:pg18
```

{C.TIMESCALE_DB} is pre-created in the default {C.PG} database and is added by default to any new database you create in this image.

</NumberedItem>

<NumberedItem title="Run the container">

Replace `</a/local/data/folder>` with the path to the folder you want to keep your data in the following command.
```
docker run -d --name timescaledb -p 5432:5432  -v </a/local/data/folder>:/pgdata -e PGDATA=/pgdata -e POSTGRES_PASSWORD=password timescale/timescaledb-ha:pg18
```

If you are running multiple container instances, change the port each Docker instance runs on.

<Callout variant="note">
If you have a local {C.PG} instance already running on port 5432, change the Docker port mapping to avoid conflicts. For example, use `-p 5433:5432` and adjust the connection string accordingly.
</Callout>

On UNIX-based systems, Docker modifies Linux IP tables to bind the container. If your system uses Linux Uncomplicated Firewall (UFW), Docker may
[override your UFW port binding settings](https://www.techrepublic.com/article/how-to-fix-the-docker-and-ufw-security-flaw/). To prevent this, add `DOCKER_OPTS="--iptables=false"` to `/etc/default/docker`.

</NumberedItem>

<NumberedItem title={`Connect to a database on your ${C.PG} instance`}>

The default user and database are both `postgres`. You set the password in `POSTGRES_PASSWORD` in the previous step. The default command to connect to {C.PG} is:

```bash
psql -d "postgres://postgres:password@127.0.0.1:5432/postgres"
```

If you changed the port mapping in step 2 (e.g., to 5433), update the port in the connection string accordingly.

</NumberedItem>

## More Docker options

If you want to access the container from the host but avoid exposing it to the
outside world, you can bind to `127.0.0.1` instead of the public interface, using this command:

```bash
docker run -d --name timescaledb -p 127.0.0.1:5432:5432 \
-v </a/local/data/folder>:/pgdata -e PGDATA=/pgdata -e POSTGRES_PASSWORD=password timescale/timescaledb-ha:pg18
```

If you don't want to install `psql` and other {C.PG} client tools locally,
or if you are using a Microsoft Windows host system, you can connect using the
version of `psql` that is bundled within the container with this command:

```bash
docker exec -it timescaledb psql -U postgres
```

When you install {C.TIMESCALE_DB} using a Docker container, the {C.PG} settings
are inherited from the container. In most cases, you do not need to adjust them.
However, if you need to change a setting, you can add `-c setting=value` to your
Docker `run` command. For more information, see the
[Docker documentation](https://hub.docker.com/_/postgres).

The link provided in these instructions is for the latest version of {C.TIMESCALE_DB}
on {C.PG} 17. To find other Docker tags you can use, see the [Dockerhub repository](https://hub.docker.com/r/timescale/timescaledb/tags?page=1&ordering=last_updated).

## View logs in Docker

If you have {C.TIMESCALE_DB} installed in a Docker container, you can view your logs
using Docker, instead of looking in `/var/lib/logs` or `/var/logs`. For more
information, see the [Docker documentation on logs](https://docs.docker.com/engine/logging/).
