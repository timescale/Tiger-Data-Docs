import * as C from "@constants";


| Key                       | Default           | Description                                                                 |
|---------------------------|-------------------|-----------------------------------------------------------------------------|
| `analytics`               | `true`            | Enable or disable usage analytics                                   |
| `color`                   | `true`            | Enable or disable colored output                                    |
| `docs_mcp`                | `true`            | Enable or disable the {C.COMPANY} documentation MCP proxy                      |
| `mcp_max_rows`            | `100`             | Set the maximum number of rows returned by the `db_query` {C.MCP_SHORT} tool          |
| `output`                  | `table`           | Set the output format to `json`, `yaml`, or `table`                         |
| `password_storage`        | `keyring`         | Set the password storage method. Options are `keyring`, `pgpass`, or `none` |
| `read_only`               | `off`             | Which {C.SERVICE_SHORT}s to protect from writes: `all` protects every {C.SERVICE_SHORT}, `prod` protects only {C.SERVICE_SHORT}s tagged `PROD`, and `off` protects none. For a protected {C.SERVICE_SHORT}, mutating `tiger service` commands and the matching {C.MCP_SHORT} tools (`create`, `fork`, `start`, `stop`, `resize`, `update-password`, and `delete`), plus `db create role`, are refused, and the database sessions opened by `db connect`, `db query`, `db connection-string`, and the `db_query` {C.MCP_SHORT} tool run in {C.CLOUD_LONG}'s immutable read-only mode, so writes and DDL are rejected by the server. Read commands and tools are unaffected. A read replica set is judged on its own environment tag, not its primary's. The legacy boolean values still work: `true` means `all` and `false` means `off` |
| `service_id`              | -                 | Set the default {C.SERVICE_SHORT} to manage                                             |
| `version_check`           | `true`            | Enable or disable checking for a new version of {C.CLI_LONG} on startup                       |

You can also set these configuration options as environment variables. Environment variables:
* Take precedence over configuration parameters values.  
* Are in upper case and use the `TIGER_` prefix. For example, `TIGER_ANALYTICS`
