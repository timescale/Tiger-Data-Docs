## Filtering a `time_bucket_gapfill()` query returns no rows or wrong counts

`HAVING` is applied before gapfilling runs, so it filters the aggregation results rather than
the gapfilled rows. A subquery does not work either, because the query planner often optimizes
it away. To filter the gapfilled rows, wrap the gapfill query in a common table expression and
filter its results. See
[`time_bucket_gapfill()`](/reference/timescaledb/hyperfunctions/time_bucket_gapfill/time_bucket_gapfill).
