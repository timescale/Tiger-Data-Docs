## Optimize time-series data using hypertables

<NumberedItem title={`Create a ${C.HYPERTABLE} for your time-series data using CREATE TABLE.`}>

For [efficient queries](/build/performance-optimization/secondary-indexes) on data in the columnstore, remember to `segmentby` the column you will
use most often to filter your data:

 ```sql
 CREATE TABLE transactions (
    time TIMESTAMPTZ NOT NULL,
    block_id INT,
    hash TEXT,
    size INT,
    weight INT,
    is_coinbase BOOLEAN,
    output_total BIGINT,
    output_total_usd DOUBLE PRECISION,
    fee BIGINT,
    fee_usd DOUBLE PRECISION,
    details JSONB
 ) WITH (
    tsdb.hypertable,
    tsdb.segmentby='block_id',
    tsdb.orderby='time DESC'
 );
 ```

 <CreateHypertablePolicyNote />

</NumberedItem>

<NumberedItem title="Create an index on the `hash` column to make queries for individual transactions faster">

```sql
CREATE INDEX hash_idx ON public.transactions USING HASH (hash);
```

</NumberedItem>

<NumberedItem title="Create an index on the `block_id` column to make block-level queries faster:">

When you create a {C.HYPERTABLE}, it is partitioned on the time column. {C.TIMESCALE_DB}
automatically creates an index on the time column. However, you'll often filter
your time-series data on other columns as well. You use [indexes](/build/performance-optimization/indexing) to improve
query performance.

```sql
CREATE INDEX block_idx ON public.transactions (block_id);
```

</NumberedItem>

<NumberedItem title="Create a unique index on the `time` and `hash` columns to prevent duplicate records">

```sql
CREATE UNIQUE INDEX time_hash_idx ON public.transactions (time, hash);
```

</NumberedItem>
