import * as C from "@constants";

import { NumberedList, NumberedItem } from "@components/NumberedList";

<NumberedList>
<NumberedItem title="Stop the jobs that are automatically adding chunks to the columnstore">
Retrieve the list of {C.JOB}s from the [timescaledb_information.jobs](/reference/timescaledb/informational-views/jobs) view
to find the {C.JOB} you need to [alter_job](/reference/timescaledb/jobs-automation/alter_job).

```sql
SELECT alter_job(JOB_ID, scheduled => false);
```
</NumberedItem>

<NumberedItem title="Convert a chunk to update back to the rowstore">
```sql
CALL convert_to_rowstore('_timescaledb_internal._hyper_2_2_chunk');
```
</NumberedItem>

<NumberedItem title="Update the data in the chunk you added to the rowstore">
Best practice is to structure your [INSERT](/build/data-management/write-data/insert) statement to include appropriate
partition key values, such as the timestamp. {C.TIMESCALE_DB} adds the data to the correct {C.CHUNK}:

```sql
INSERT INTO metrics (time, value)
VALUES ('2025-01-01T00:00:00', 42);
```
</NumberedItem>

<NumberedItem title="Convert the updated chunks back to the columnstore">
```sql
CALL convert_to_columnstore('_timescaledb_internal._hyper_1_2_chunk');
```
</NumberedItem>

<NumberedItem title="Restart the jobs that are automatically converting chunks to the columnstore">
```sql
SELECT alter_job(JOB_ID, scheduled => true);
```
</NumberedItem>
</NumberedList>
