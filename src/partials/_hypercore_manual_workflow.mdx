1. **Stop the jobs that are automatically adding {C.CHUNK}s to the {C.COLUMNSTORE}**

   Retrieve the list of {C.JOB}s from the [timescaledb_information.jobs](/api/informational-views/jobs/) view
   to find the {C.JOB} you need to [alter_job](/api/jobs-automation/alter_job/).

   ``` sql
   SELECT alter_job(JOB_ID, scheduled => false);
   ```

1. **Convert a {C.CHUNK} to update back to the {C.ROWSTORE}**

      ``` sql
      CALL convert_to_rowstore('_timescaledb_internal._hyper_2_2_chunk');
      ```

1. **Update the data in the {C.CHUNK} you added to the {C.ROWSTORE}**

   Best practice is to structure your [INSERT](/use-timescale/write-data/insert/) statement to include appropriate
   partition key values, such as the timestamp. {C.TIMESCALE_DB} adds the data to the correct {C.CHUNK}:

   ``` sql
   INSERT INTO metrics (time, value)
   VALUES ('2025-01-01T00:00:00', 42);
   ``` 

1. **Convert the updated {C.CHUNK}s back to the {C.COLUMNSTORE}**

   ``` sql
   CALL convert_to_columnstore('_timescaledb_internal._hyper_1_2_chunk');
   ```

1. **Restart the {C.JOB}s that are automatically converting {C.CHUNK}s to the {C.COLUMNSTORE}**

   ``` sql
   SELECT alter_job(JOB_ID, scheduled => true);
   ```
