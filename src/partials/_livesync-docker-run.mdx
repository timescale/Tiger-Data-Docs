import * as C from "@constants";

Best practice is to run as a Docker daemon:

```bash
docker run -d --rm --name livesync timescale/live-sync:latest run \
  --publication <publication_name> \
  --subscription <subscription_name> \
  --source "$SOURCE" \
  --target "$TARGET"
```

`latest` is the latest available version. See [Docker Hub](https://hub.docker.com/r/timescale/live-sync).

| Flag | Description |
| --- | --- |
| `--publication` | Publication name as created in the publication step. Repeat the flag for multiple publications. |
| `--subscription` | Name that identifies the subscription on the target. |
| `--source` | Connection string to the source {C.PG} database. |
| `--target` | Connection string to the target {C.SERVICE_LONG}. |
| `--table-map` | (Optional) JSON mapping source tables to target tables. Repeat for multiple mappings; the first matching mapping wins. `source.table` is a Go regular expression, anchored automatically, so one mapping can merge many source tables into one target. See the example below the table, and [Consolidate multiple source tables into one hypertable](/migrate/livesync-replication#consolidate-multiple-source-tables-into-one-hypertable). |
| `--table-sync-workers` | (Optional) Number of parallel workers for initial table sync. Default: 4. |
| `--copy-data` | (Optional) Set to `false` to skip initial data copy and only replicate changes made after replication slot creation. Useful for dry-run testing. Default: `true`. |

Example `--table-map` value that syncs `public.metrics` to `public.metrics_data`:

```bash
--table-map '{"source": {"schema": "public", "table": "metrics"}, "target": {"schema": "public", "table": "metrics_data"}}'
```
