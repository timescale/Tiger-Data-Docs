Use [`tiger service list`](/reference/tiger-cloud/tiger-cli#tiger-service-list) to find the ID of the {C.SERVICE_SHORT} you want to manage, then run the relevant command. All commands require you to be [logged in](/get-started/quickstart/tiger-cli).

<Callout variant="note">

Changing the environment of an existing {C.SERVICE_SHORT} and converting a free {C.SERVICE_SHORT} to a standard one are only available in {C.CONSOLE}. See the [{C.CONSOLE} tab](#tab=tiger-console). {C.CLI_LONG} sets the environment tag only when it creates a {C.SERVICE_SHORT}, with `tiger service create --environment` or `tiger service fork --environment`.

</Callout>

## Reset your {C.SERVICE_SHORT} password with {C.CLI_LONG}

To reset the password used to connect to your {C.SERVICE_SHORT}:

```bash
# Prompt for a new password interactively
tiger service update-password <service-id>

# Auto-generate a secure password
tiger service update-password <service-id> --auto-generate
```

With `--auto-generate`, you see something like:

```txt
Password saved to system keyring
View it with: tiger service get <service-id> --with-password
Password updated for tsdbadmin
```

This updates the password for the `tsdbadmin` database user, not your {C.CONSOLE_SHORT} account. To switch the authentication type between SCRAM and MD5, see the [{C.CONSOLE} tab](#tab=tiger-console).

<Callout variant="warning">

Resetting the password immediately invalidates the old one. Any application, automation, or integration that connects with the previous credentials loses access until you update its connection details.

</Callout>

## Pause a {C.SERVICE_SHORT} with {C.CLI_LONG}

To stop a {C.SERVICE_SHORT} temporarily without deleting it:

```bash
tiger service stop <service-id>
```

You see something like:

```txt
Stop request accepted for service '<name>' (<service-id>).
Waiting for service to stop (timeout: 10m0s)...
Service stopped.
```

You are no longer billed for compute, but storage billing continues. To start the {C.SERVICE_SHORT} again:

```bash
tiger service start <service-id>
```

You see something like:

```txt
Start request accepted for service '<name>' (<service-id>).
Waiting for service to start (timeout: 10m0s)...
Service started.
```

## Delete a {C.SERVICE_SHORT} with {C.CLI_LONG}

Deleting a {C.SERVICE_SHORT} is irreversible and permanently removes it and all its data. {C.CLI_SHORT} prompts you to type the service ID to confirm:

```bash
tiger service delete <service-id>
```

You see something like:

```txt
Service '<name>' (<service-id>) deleted.
```

<Callout variant="warning">

{C.CLI_SHORT} doesn't enforce the delete protection {C.CONSOLE} applies to production {C.SERVICE_SHORT}s. With `read_only` off, the default, `tiger service delete` deletes a production {C.SERVICE_SHORT} the same way it deletes a development one. To have it refused, set `read_only` to `prod` or `all`.

</Callout>
