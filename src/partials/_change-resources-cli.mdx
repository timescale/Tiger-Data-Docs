## Update compute resources for a {C.SERVICE_SHORT} with {C.CLI_LONG}

Use [`tiger service list`](/reference/tiger-cloud/tiger-cli#tiger-service-list) to find the ID of the {C.SERVICE_SHORT} you want to resize, then set the new CPU and memory allocation. CPU is given in cores, memory in gigabytes:

```bash
tiger service resize <service-id> --cpu 4 --memory 16
```

You see something like:

```txt
Resizing service '<name>' (<service-id>) to 4 CPU/16 GB.
The resize is in progress and may take several minutes to complete.
```

The allowed combinations are:

| CPU     | Memory |
| ------- | ------ |
| 0.5 CPU | 2 GB   |
| 1 CPU   | 4 GB   |
| 2 CPU   | 8 GB   |
| 4 CPU   | 16 GB  |
| 8 CPU   | 32 GB  |
| 16 CPU  | 64 GB  |
| 32 CPU  | 128 GB |

32 CPU / 128 GB is the largest allocation {C.CLI_LONG} accepts. To resize to 48 CPU / 192 GiB or 64 CPU / 256 GiB, use the [{C.CONSOLE} tab](#tab=tiger-console).

If you set only `--cpu` or only `--memory`, {C.CLI_LONG} configures the other value to match.

The command returns as soon as the request is accepted. Check progress with
[`tiger service get`](/reference/tiger-cloud/tiger-cli#tiger-service-get).

For the full list of flags, see the [{C.CLI_LONG} reference](/reference/tiger-cloud/tiger-cli).
