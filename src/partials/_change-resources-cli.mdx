## Update compute resources for a {C.SERVICE_SHORT}

Use `tiger service list` to find the ID of the {C.SERVICE_SHORT} you want to resize, then set the new CPU and memory allocation. CPU is given in millicores, memory in gigabytes:

```bash
tiger service resize <service-id> --cpu 4000 --memory 16
```

The allowed combinations are:

| CPU     | Millicores | Memory |
| ------- | ---------- | ------ |
| 0.5 CPU | `500`      | 2 GB   |
| 1 CPU   | `1000`     | 4 GB   |
| 2 CPU   | `2000`     | 8 GB   |
| 4 CPU   | `4000`     | 16 GB  |
| 8 CPU   | `8000`     | 32 GB  |
| 16 CPU  | `16000`    | 64 GB  |
| 32 CPU  | `32000`    | 128 GB |

32 CPU / 128 GB is the largest allocation {C.CLI_LONG} accepts. To resize to 48 CPU / 192 GiB or 64 CPU / 256 GiB, use the [{C.CONSOLE} tab](#tab=tiger-console).

If you set only `--cpu` or only `--memory`, {C.CLI_LONG} configures the other value to match.

`tiger service resize` waits for the resize to finish. To return immediately instead, add `--no-wait`. To change how long it waits, use `--wait-timeout`:

```bash
tiger service resize <service-id> --cpu 4000 --memory 16 --no-wait
```

For the full list of flags, see the [{C.CLI_LONG} reference](/reference/tiger-cloud/tiger-cli).
