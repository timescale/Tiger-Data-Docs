## Prerequisites

<PrereqCloud />

- Install the [{C.PG} client tools](/integrations/psql/) on your sync machine.

- Ensure that the source {C.PG} instance and the target {C.SERVICE_LONG} have the same extensions installed.

  The {C.PG_CONNECTOR} does not create extensions on the target. If the table uses column types from an extension,
    first create the extension on the target {C.SERVICE_LONG} before syncing the table.

## Limitations

* The source {C.PG} instance must be accessible from the Internet.

  Services hosted behind a firewall or VPC are not supported. This functionality is on the roadmap. 

* Indexes, including the primary key, unique constraints, and sequences are not migrated to the target {C.SERVICE_LONG}.

  We recommend that, depending on your query patterns, you create only the necessary indexes on the target {C.SERVICE_LONG}.

<LivesyncLimitations />

## Set your connection string

This variable holds the connection information for the source database. In the terminal on your migration machine, 
set the following:

```bash
export SOURCE="postgres://<user>:<password>@<source host>:<source port>/<db_name>"
```

<Callout variant="tip">

Avoid using connection strings that route through connection poolers like PgBouncer or similar tools. This tool 
requires a direct connection to the database to function properly.

</Callout>

## Synchronize data to your {C.SERVICE_LONG}

To sync data from your {C.PG} database to your {C.SERVICE_LONG} using {C.CONSOLE}:

<NumberedList>

<NumberedItem title={`Connect to your ${C.SERVICE_LONG}`}>

In [{C.CONSOLE}](https://console.cloud.timescale.com/dashboard/services), select the {C.SERVICE_SHORT} to sync live data to.

</NumberedItem>

<NumberedItem title={`Connect the source database and the target ${C.SERVICE_SHORT}`}>

![{C.PG} connector wizard][postgres-connector-wizard]

1. Click `Connectors` > `{C.PG}`.
1. Set the name for the new connector by clicking the pencil icon.
1. Check the boxes for `Set wal_level to logical` and `Update your credentials`, then click `Continue`.
1. Enter your database credentials or a {C.PG} connection string, then click `Connect to database`. 
   This is the connection string for [`<pg connector username>`](/migrate/livesync-for-postgresql/#tune-your-source-database). {C.CONSOLE} connects to the source database and retrieves the schema information.

</NumberedItem>

<NumberedItem title={`Optimize the data to synchronize in ${C.HYPERTABLE}s`}>

![{C.PG} connector start][postgres-connector-start]

1. In the `Select table` dropdown, select the tables to sync.
1. Click `Select tables +` .    

   {C.CONSOLE} checks the table schema and, if possible, suggests the column to use as the time dimension in a {C.HYPERTABLE}.
1. Click `Create Connector`.

   {C.CONSOLE} starts {C.PG_CONNECTOR} between the source database and the target {C.SERVICE_SHORT} and displays the progress.

</NumberedItem>

<NumberedItem title="Monitor synchronization">

![Tiger Cloud connectors overview](https://assets.timescale.com/docs/images/tiger-on-azure/tiger-console-connector-overview.png)

 1. To view the amount of data replicated, click `Connectors`. The diagram in `Connector data flow` gives you an overview of the connectors you have created, their status, and how much data has been replicated.  

 1. To review the syncing progress for each table, click `Connectors` > `Source connectors`, then select the name of your connector in the table.

</NumberedItem>

<NumberedItem title="Manage the connector">

![Edit a {C.PG} connector][edit-a-postgres-connector]

1. To edit the connector, click `Connectors` > `Source connectors`, then select the name of your connector in the table. You can rename the connector, delete or add new tables for syncing.

1. To pause a connector, click `Connectors` > `Source connectors`, then open the three-dot menu on the right and select `Pause`. 

1. To delete a connector, click `Connectors` > `Source connectors`, then open the three-dot menu on the right and select `Delete`. You must pause the connector before deleting it.

</NumberedItem>

</NumberedList>

And that is it, you are using the {C.PG_CONNECTOR} to synchronize all the data, or specific tables, from a {C.PG} database 
instance to your {C.SERVICE_LONG}, in real time.
