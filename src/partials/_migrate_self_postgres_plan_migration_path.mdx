Best practice is to always use the latest version of {C.TIMESCALE_DB}. Subscribe to our releases on GitHub or use {C.CLOUD_LONG} 
and always run the latest update without any hassle. 

Check the following support matrix against the versions of {C.TIMESCALE_DB} and {C.PG} that you are running currently
and the versions you want to update to, then choose your upgrade path.

For example, to upgrade from {C.TIMESCALE_DB} 2.13.x on {C.PG} 13 to {C.TIMESCALE_DB} 2.25.x:
1. Upgrade {C.TIMESCALE_DB} to 2.15.x (last version fully supporting {C.PG} 13)
1. Upgrade {C.PG} to 15, 16, 17, or 18
1. Upgrade {C.TIMESCALE_DB} to 2.25.x

Older {C.TIMESCALE_DB} versions may not be available in package repositories. If you need a specific intermediate
version that is no longer packaged, you can [build from source](/get-started/choose-your-path/install-timescaledb) or upgrade directly
to the latest version that supports your current {C.PG} version before upgrading {C.PG}.

You may need to upgrade to the latest {C.PG} version before you upgrade {C.TIMESCALE_DB}. Also,
if you use [{C.TOOLKIT_LONG}](/deploy/self-hosted/tooling/install-toolkit), ensure the `timescaledb_toolkit` extension is >=  
v1.6.0 before you upgrade {C.TIMESCALE_DB} extension.
