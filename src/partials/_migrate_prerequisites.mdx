- A target [{C.SERVICE_LONG}](/get-started/quickstart/create-service).

  Best practice is to create a {C.SERVICE_LONG} with at least 8 CPUs for a smoother experience. A higher-spec instance
  can significantly reduce the overall migration window.

- A migration machine to run the commands that move data from your source database to your target {C.SERVICE_LONG}.

  Best practice: use an [Ubuntu EC2 instance](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/EC2_GetStarted.html#ec2-launch-instance) hosted in the same region as your {C.SERVICE_LONG}.

- An [adjusted maintenance window](/deploy/tiger-cloud/tiger-cloud-aws/upgrades#define-your-maintenance-window) to prevent maintenance from running during migration.
