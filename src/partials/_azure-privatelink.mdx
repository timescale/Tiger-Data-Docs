## Set up a private endpoint connection

Take the following steps to connect your {C.SERVICE_LONG} to a Private Link endpoint.

<NumberedList>

<NumberedItem title="Copy the alias for your region">

1. In [{C.CONSOLE_LONG}](https://console.cloud.tigerdata.com/dashboard/azure-privatelink), select `Security` > `Private Endpoints` > `Manage endpoints`.
1. Under `Create the endpoint`, copy the `Alias` for the region in which you need to create the connection. Choose the region closest to your Azure resources for optimal performance.

   <ThemeImage light={imgManagePrivateEndpointsLight} dark={imgManagePrivateEndpointsDark} alt="Copying the region alias in the Manage endpoints panel" />

</NumberedItem>

<NumberedItem title="Create a private endpoint in Azure">

1. In [Azure Portal](https://azure.microsoft.com/en-us/get-started/azure-portal), go to `Private endpoints` and click `Create`.

   <ThemeImage light={imgCreatePrivateEndpointAzureLight} dark={imgCreatePrivateEndpointAzureDark} alt="Create Azure Private Endpoint" />

1. In `Subscription`, select the subscription that contains the resources you want to connect to {C.CLOUD_LONG}.
1. In `Resource group`, select an existing resource group or create a new one for your private endpoint.
1. Provide a name for your endpoint.
1. Select the region where your Virtual Network is deployed, then click `Next: Resource`.
1. In `Connection method`, select `Connect to an Azure resource by resource ID or alias`.
1. In `Resource ID or alias`, paste the alias you have copied from {C.CONSOLE_LONG}.
1. Leave `Request message` empty, then click `Next: Virtual Network`.
1. Select the Virtual Network that contains the resources you want to connect to {C.CLOUD_LONG}, then choose the subnet where the endpoint's private IP will be created. Optionally select an application security group, then click `Next: DNS`.
1. Optionally configure private DNS integration and tags for your endpoint, then click `Next: Review + create`.
1. Review your config and click `Create`. Azure creates your private endpoint. Wait for the deployment to succeed.
1. Go to your private endpoint's `Overview`. Once {C.CLOUD_LONG} approves the connection, the connection status message reads `Connected. Claim this connection in the console using ID <ID>`. Copy this ID; you claim the connection with it.

   <ThemeImage light={imgPrivateEndpointOverviewAzureLight} dark={imgPrivateEndpointOverviewAzureDark} alt="The connection status message on an Azure private endpoint" />

   <Callout variant="note">

   Approval takes up to a few minutes. The ID is your endpoint's `resourceGuid`, so you can also read it from `JSON View` under `properties` if you prefer.

   </Callout>

1. Go to `Private endpoints` and copy the private endpoint IP from the `Private IP` column.

</NumberedItem>

<NumberedItem title="Claim the connection">

1. In [{C.CONSOLE_LONG}](https://console.cloud.tigerdata.com/dashboard/azure-privatelink) > `Security` > `Private Endpoints`, click `Manage endpoints`.
1. Under `Claim it`, paste the ID you copied into `Endpoint identifier`, then click `Claim connection`. {C.CLOUD_LONG} links the connection to the project you are working in, and it appears in the list.

   <ThemeImage light={imgClaimPrivateEndpointLight} dark={imgClaimPrivateEndpointDark} alt="Claiming a private endpoint connection with the endpoint identifier" />

   <Callout variant="note">

   You can claim a private endpoint against one project only.

   </Callout>

</NumberedItem>

<NumberedItem title="Attach a service">

Under `Services` click `Attach service`. Select your {C.SERVICE_SHORT} from the dropdown and click `Attach`. You can attach a {C.SERVICE_SHORT} to one private endpoint.

</NumberedItem>

<NumberedItem title="Publish the service hostname in your private DNS">

You resolve your {C.SERVICE_SHORT} hostname to your private endpoint in a private DNS zone that you control.

1. In [Azure Portal](https://azure.microsoft.com/en-us/get-started/azure-portal), create a [private DNS zone](https://learn.microsoft.com/en-us/azure/dns/private-dns-getstarted-portal) named `<project-id>.tsdb.cloud.timescale.com`, then add a [virtual network link](https://learn.microsoft.com/en-us/azure/dns/private-dns-virtual-network-links) to the Virtual Network that contains your resources. If you already have a private DNS zone for this domain, use it.
1. In that zone, create an `A` record for your {C.SERVICE_SHORT} hostname, `<service-id>.<project-id>.tsdb.cloud.timescale.com`, that resolves to the private endpoint IP you copied from Azure Portal. An Azure private endpoint has a single IP address, so an `A` record is correct here.
1. If you use a read replica, add a second `A` record for `<service-id>-repl.<project-id>.tsdb.cloud.timescale.com` pointing at the same IP. The connection pooler uses the same hostname as the primary, so it needs no extra record.

   Find your {C.SERVICE_SHORT} ID and {C.PROJECT_SHORT} ID in your [connection details](/integrate/find-connection-details).

<Callout variant="note">

You publish the standard {C.SERVICE_SHORT} hostname, the same one used over the public internet. This means your existing connection strings work unchanged, and the {C.SERVICE_SHORT} certificate already covers the name, so `sslmode=verify-full` keeps working with no certificate changes.

</Callout>

</NumberedItem>

<NumberedItem title="Test the connection">

From a VM inside your Azure VNet, connect to your {C.SERVICE_SHORT} using a connection string with your [connection details](/integrate/find-connection-details). You should be able to connect successfully.

<Callout variant="warning">

Ports are specific to each endpoint, and are not `5432`. Your primary and your read replica listen on different ports. Always use the port shown for that endpoint in your [connection details](/integrate/find-connection-details).

</Callout>

</NumberedItem>

</NumberedList>

## Migrate from a configured IP address

Previously, you configured a private endpoint by adding the endpoint IP address in {C.CONSOLE_LONG}, and {C.CLOUD_LONG} published the DNS records for you. That flow is retired. If your connection still has an IP address configured, move it to your own private DNS.

<NumberedList>

<NumberedItem title="Publish the hostname in your own zone">

Create the records described in [Publish the service hostname in your private DNS](#set-up-a-private-endpoint-connection), then confirm from inside your Virtual Network that your {C.SERVICE_SHORT} hostname resolves to your private endpoint and that you can connect.

</NumberedItem>

<NumberedItem title={`Remove the IP address in ${C.CONSOLE_LONG}`}>

In `Security` > `Private Endpoints`, remove the IP address from your connection. This deletes the DNS records that {C.CLOUD_LONG} published and hands resolution to your zone.

<Callout variant="warning">

Removing the IP address is one way. Your own zone must already resolve the {C.SERVICE_SHORT} hostname before you remove it, otherwise connections fail until you finish setting up your DNS.

</Callout>

</NumberedItem>

</NumberedList>

## Manage connections

- To detach a {C.SERVICE_SHORT} from a private endpoint connection, go to `Security` > `Private Endpoints`, expand the arrow in the `Services` column, and click the trash icon next to the {C.SERVICE_SHORT} connection string.
- To edit or remove an endpoint connection, go to `Security` > `Private Endpoints` and click the three dots next to the connection in the list. Select `Edit` or `Disconnect`, respectively. You need to detach all {C.SERVICE_SHORT}s from a private endpoint connection before deleting it.
