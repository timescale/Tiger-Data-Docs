## Optimize time-series data in a hypertable

<HypertableIntro />

<NumberedList>

<NumberedItem title={`Connect to your ${C.SERVICE_LONG}`}>

In [{C.CONSOLE}](https://console.cloud.timescale.com/dashboard/services) open an [SQL editor](/build/data-management/run-queries-from-tiger-console). You can also connect to your service using [psql](/integrate/query-administration/psql).

</NumberedItem>

<NumberedItem title={`Create a ${C.HYPERTABLE} to store the real-time cryptocurrency data`}>

Create a [{C.HYPERTABLE}](/build/data-management/understand-hypertables) for your time-series data using [CREATE TABLE](/reference/timescaledb/).
For [efficient queries](/build/columnar-storage/secondary-indexes) on data in the columnstore, remember to `segmentby` the column you will
use most often to filter your data:

 ```sql
 CREATE TABLE crypto_ticks (
     "time" TIMESTAMPTZ,
     symbol TEXT,
     price DOUBLE PRECISION,
     day_volume NUMERIC
 ) WITH (
    tsdb.hypertable,
    tsdb.segmentby='symbol',
    tsdb.orderby='time DESC'
 );
 ```

## Create a standard {C.PG} table for relational data

When you have relational data that enhances your time-series data, store that data in
standard {C.PG} relational tables.

<NumberedList>

<NumberedItem title="Add a table to store the asset symbol and name in a relational table">

```sql
CREATE TABLE crypto_assets (
    symbol TEXT UNIQUE,
    "name" TEXT
);
```

</NumberedItem>

</NumberedList>

You now have two tables within your {C.SERVICE_LONG}. A hypertable named `crypto_ticks`, and a normal
{C.PG} table named `crypto_assets`.
